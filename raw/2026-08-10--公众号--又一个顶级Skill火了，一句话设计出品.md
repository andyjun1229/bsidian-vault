上次我写了那个一句话克隆任意网站的 Skill，不少朋友看完去试了，传送门：

又一个顶级 Skill 火了，一句话克隆任意网站！

很多朋友留言反映，克隆出来一个一模一样的网站，意义不大，没什么实际的使用场景。仔细想想确实是这样，别人的页面你不可能真拿去用，练手学习可以，落到自己的项目上就不行了。真正有价值的是那个网站背后的设计语言，颜色怎么配的，字体怎么定的，组件是什么风格，这些东西才能用在你自己的项目上。

刚好前几天我在 GitHub Trending 上刷到一个仓库，awesome-design-md，今年三月底才建的，现在已经 10.7 万 Star。它干的事就是把一批知名网站的设计语言提前提取好，做成现成的文档，你拿过来直接用在自己的项目里。我把文档翻了一遍，又在 Codex 里实际用了一次，这篇聊聊它是什么，怎么用。

简介

先解释下 DESIGN.md，这是 Google Stitch 提出的一个概念，一个纯文本的设计系统文档，专门给 AI 编程工具读的。放到项目根目录，AI 生成界面的时候就照着里面的规则来，颜色、字体、按钮样式，都写在文件里。

awesome-design-md 这个仓库，就是把真实网站的设计语言提前提取好，做成一份份现成的 DESIGN.md。目前官方标的是 73 份，Stripe、Linear、Vercel、Notion、Apple、Tesla 这些都在里面，MIT 协议，可以直接拿来用。

这个仓库里都有什么

73 份大厂设计文档，按行业分好了类

仓库里把 73 份文档按行业分了组，翻起来很方便。

AI 有 Claude、xAI、Mistral、Ollama；开发者工具有 Cursor、Vercel、Warp、Raycast；SaaS 有 Linear、Notion、Cal.com、Intercom；金融有 Stripe、Coinbase、Revolut、Wise；消费品牌有 Apple、Nike、星巴克、Spotify；汽车更全，特斯拉、法拉利、兰博基尼、宝马、布加迪都有。

还有个挺有意思的彩蛋，仓库里有个复古区，收了戴尔 1996 年的官网和任天堂 2001 年的官网设计语言。哪天想做个千禧年风格的页面，直接就能用。

一份 DESIGN.md 里都写了什么

我打开 Stripe 那份仔细看了一下，每份文档固定分九个部分：视觉氛围、色板、字体规则、组件样式、布局原则、阴影层级、设计红线、响应式行为、给 AI 的提示词指南。

拿色板来说，它不是简单列几个颜色完事，每个色值都标了语义名和用途。主色 

#533afd

，按下状态的深色 

#2e2b8c

，边框色 

#e3e8ee

，正文墨色 

#0d253d

。AI 拿到这份东西，就知道哪个颜色该用在哪个地方，不用自己瞎配。

字体那段写得更细。标题用 Sohne 字体 300 字重，56px 的行高 1.03，字间距 -1.4px，连字体特性参数都写进去了。正文、标题、辅助文字各自一套完整参数。

最后还有个 Do's and Don'ts 部分，直接告诉 AI 这种风格下什么能做什么不能做，等于把设计评审的意见提前写好了。我觉得这部分反而是最有用的，AI 自由发挥时犯的那些毛病，基本就集中在这几类。

我在 Codex 里实际用了一次

用法比我想的还简单。我把 Linear 那份 DESIGN.md 拷到项目根目录，然后跟 Codex 说：

读一下项目根目录的 DESIGN.md，严格按照里面的设计语言，给我做一个 SaaS 产品的落地页

跑出来的页面，简约大气、窄字距的大标题、大段克制的留白，确实是 Linear 那个味道。

使用这个Kill，生成的UI效果

我又试了一次不给任何设计约束，让 AI 自由发挥，出来的还是老样子，大渐变背景加圆角卡片。不是说不好看，有点炫酷，但是千篇一律，一看就是 AI 生成的。

没使用Skill生成的效果

另外每个网站的文件夹里都带了 

preview.html

 和 

preview-dark.html

，浏览器直接打开就能看到这套设计的色板、字体层级、按钮和卡片的实际样子。用之前可以先翻一翻，挑个自己顺眼的再动手。

想要的网站没有，可以提需求

仓库作者开了个申请通道，想要哪个网站的 DESIGN.md，可以去 

getdesign.md/request

 提交，还支持私有请求，做出来只发给你。现在 70 多份，照这个热度，后面肯定还会涨。

快速开始

第一步，把仓库拉下来，或者直接去 GitHub 页面下载你要的那一份：

git

 clone

 https://github.com/VoltAgent/awesome-design-md.git

所有文档都在 design-md 目录下，一个网站一个文件夹。

第二步，把你要用的那份 DESIGN.md 拷到自己项目的根目录。

第三步，跟你的 AI 编程工具说一声，Codex、Claude Code、Cursor 都行：

按照根目录 DESIGN.md 里的设计规范，实现这个页面

就这三步，整个过程不用装依赖，不用配 MCP，也不用开浏览器做侦察，比上次克隆网站的流程简单不少。

使用场景

说几个我自己觉得靠谱的场景。

1、做 side project 和内部工具：

 大部分程序员做的页面丑，不是代码能力的问题，是没有设计依据。丢一份 DESIGN.md 进去，下限至少兜住了。

2、做 demo 和原型：

 黑客松、给客户演示、产品早期验证，都需要快速出一个看着像样的界面。直接借一套成熟的设计语言，比让 AI 自由发挥稳得多。

3、团队没有设计师：

 小团队起步阶段，先拿一套现成的设计规范打底，等产品跑起来了，再考虑做自己的品牌设计。

还有一个用法，如果你本来就喜欢某个网站的风格，比如 Linear 那种极简风，可以直接把它的 DESIGN.md 当成你项目的长期设计规范。以后所有页面都让 AI 照着这份文件生成，风格能一直保持统一，不会今天一个样明天一个样。

最后聊聊

我觉得这个仓库解决的是一个挺实际的问题，现在 AI 写前端代码，能力上早就不缺了，但出来的页面经常丑得差不多，渐变背景、紫色、圆角卡片，翻来覆去就那一套。原因也简单，AI 没有设计依据，只能按它见得最多的风格来。DESIGN.md 给的就是这个依据，而且是大厂设计师定好的依据，比我们自己瞎描述一通要靠谱得多。

上次克隆网站那篇发出来之后，我也一直在想这类工具到底该怎么用。克隆得到的是一个和别人一样的页面，这个仓库帮你做的是一个属于你自己的、但看着很专业的页面。对我们这种没有设计师的个人开发者来说，后面这个明显更有用。

当然也有不足，网站就 70 多个，你想要的未必有。色值这些是从公开 CSS 里提取出来的，跟人家内部完整的设计系统肯定有差距。还有字体，像 Stripe 的 Sohne 是人家买的商业字体，你本机没有就用不了，好在文档里都写了 fallback 方案，实际影响不大。

最后多说一句，借人家的设计语言做自己的东西，我觉得问题不大，按我的理解，设计风格这东西本身不在版权保护的范围里。但别顺手把人家的文案和图片素材也搬走，那就完全是另一回事了。
