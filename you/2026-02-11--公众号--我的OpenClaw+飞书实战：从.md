核心代码其实不复杂，大概

200行。核心是多因子评分系统：

// python

# investment_agent.py

class QuantAgent:

    def fetch_market_data(self):

        """从腾讯财经获取实时数据"""

        stocks = self._load_stock_list()  # 93只核心标的

        # 半导体、AI软件、新能源、消费电子、游戏传媒...

        return self._call_tencent_api(stocks)

    def calculate_alpha_factors(self, data):

        """计算多因子评分"""

        for stock in data:

            stock['score'] = (

                self._momentum_factor(stock) * 0.3 +

                self._volume_factor(stock) * 0.25 +

                self._trend_factor(stock) * 0.25 +

                self._ml_prediction(stock) * 0.20  # ML权重20%

            )

        return data

为什么要加重试机制？因为股市

API偶尔会超时。

前天收盘报告就漏发了，今天早上才发现。我检查了一下日志，发现是

API超时导致的任务失败。所以加了一个重试任务，5分钟后如果主任务没成功就重发。

这个系统让我踩过两个坑。

坑

1：日期逻辑错误

一开始代码直接用

datetime.now()

生成报告文件名。结果有一次任务延迟到第二天早上执行，文件名就变成了第二天的日期。我一看目录里少了前一天的报告，还以为出

bug了。

修复方案其实很简单：

// python

if report_type == 'evening' and now.hour < 9:

    # 早上运行 evening 任务，说明是补发前一天的

    date_str = (now - timedelta(days=1)).strftime("%Y-%m-%d")

但这个坑让我反思了一下：很多边界情况都是没想到的。你写代码的时候只考虑了正常流程，但实际运行时会遇到各种意外。这也算是一个教训

——做自动化系统，异常处理比正常流程更重要。

坑

2：飞书消息长度限制

早期报告太长，飞书截断了。我一开始还没发现，因为截断的部分正好在末尾，不太明显。直到有一天报告特别长，截断了一半重要内容，我才注意到。

后来学会了分段发送，或者用飞书卡片格式。现在每段

1. 重试机制确保可靠性

金融市场不能漏报，所以我设计了双重保险：

主任务

 9:25 执行

            

↓

这个机制让我避免了昨天漏发报告的情况。虽然只是一个小细节，但在生产环境里很重要。

2. 人机协同的分工

我一开始想让

AI完全自动，但后来发现不对。

有些事机器做得更好：数据采集和清洗、格式化和排版、定时推送、错误重试。

有些事必须人做：投资决策（买卖）、内容审核（重要报告）、策略调整（因子权重）、异常处理（系统故障）。

我觉得这才是正确的方向：

让机器做它擅长的，让人做人擅长的

。

故障处理记录

生产环境的系统，故障是不可避免的。这里记录几个真实故障。

故障

1：昨天收盘报告未发送

现象：用户反馈昨天收盘报告没收到

排查：

// bash

ls -la reports/ | grep evening

# 发现只有 2026-02-09_evening.md，没有 2026-02-10_evening.md

根因：

cron 任务执行时 API 超时，但重试机制也没触发（任务被 kill）

解决：

1. 

手动补发报告

2. 

优化日期逻辑（见上文）

3. 

增加任务超时保护

故障

2：电网学习内容太长被截断

解决：

// python

# 分段发送

if len(content) > 3000:

    chunks = [content[i:i+3000] for i in range(0, len(content), 3000)]

    for chunk in chunks:

        send_to_feishu(chunk)

故障

3：飞书消息偶尔发不出去

解决：检查飞书

 API 限流，增加指数退避重试：

// python

for attempt in range(3):

    try:

        send_message()

        break

    except RateLimitError:

        time.sleep(2 ** attempt)  # 2s, 4s, 8s

这些故障处理让我意识到：

自动化系统不是一劳永逸的，需要持续监控和维护

。但维护成本比手动做这些事低太多了。

ROI这么高。当然，时间价值每个人不一样，但对于我来说，这88小时可以用来做更有价值的事。

而且这个成本是一次性的投入，后面只需要付

API费用。我算了一下，假设这套系统跑半年，平均下来每个月也就100块出头。

下一步计划

这套系统已经稳定运行

2周了，但我觉得还能做更多。

投资系统增强

我想接入更多数据源（东方财富、雪球），增加回测功能，接入模拟交易。这样可以在真实交易前先测试一下策略。

知识库问答

把电网知识做成

RAG，支持飞书里直接提问。这样我可以像问ChatGPT一样问电力系统的问题，但基于我自己整理的内容。

周报自动化

汇总每日简报生成周报，自动发送给团队。这样可以减少一些团队内部的信息同步成本。

结语

说起来，这套系统让我重新思考了

"自动化"这件事。

以前我觉得自动化就是

"完全替代人"，什么都让机器做。但现在我意识到，

自动化不是替代思考，而是消除重复

。

让机器做它擅长的（采集、计算、格式化），让人做人擅长的（判断、创造、决策）。这才是正确的方向。
