这不是一次普通的功能迭代，而是 OpenClaw 从"开源框架"向"AI Agent 平台"的战略转型宣言。

tags: [公众号]

一、先说结论：OpenClaw 想通了

昨晚的更新，我第一反应是——终于。

从去年开始，我就在观察这个项目。早期的 OpenClaw 像极了一个技术极客的玩具：功能丰富、扩展性强、但总觉得哪里有点散。

这次的更新，把所有"散"的东西，全部收回来了。

如果你只看更新日志，可能会觉得"哦，又是一些 Breaking Changes"。但如果你仔细看这 6 个大改动背后的逻辑，会发现一个清晰的信号：

> 👉 OpenClaw 不再满足于做一个"框架"，它要做一个"平台"。

框架和平台的区别是什么？

- 框架说：我给你工具，你自己玩
- 平台说：你在我这玩，我保证体验一致

这次更新，就是在完成这个身份转换。

---

二、六个改动，看懂一个战略

改动 1：ClawHub 成为默认入口

表面看：安装插件优先走 ClawHub，没有才 fallback 到 npm。

实际上：这是生态主权的宣示。

以前 OpenClaw 的插件体系和 npm 深度绑定，好处是借力打力—— npm 上海量的包都能用。但坏处也很明显：

- 质量参差不齐，一个坏包可能搞崩整个系统
- 版本管理混乱，依赖地狱随时可能爆发
- 无法做针对性的优化和审核

现在把 ClawHub 放到 C 位，意味着 OpenClaw 要掌控自己的生态。

这就像苹果搞 App Store、微信搞小程序平台。只有掌控了分发入口，才能保证体验的一致性，才能建立真正的护城河。

对开发者的影响：
- 好消息：插件质量会有基本保障，用户踩坑少了
- 坏消息：发布门槛变高了，得按平台的规则来

---

改动 2：插件体系大重构

表面看：SDK 路径变了、消息机制重写了、运行方式调整了。

实际上：这是在统一插件的"行为边界"。

之前的插件体系有点像" Wild West"—— 插件能干的事情太多，权限太大，调用方式也不统一。这带来的问题是：

- 安全风险：插件可能做不该做的事
- 兼容性问题：不同插件之间可能冲突
- 维护成本高：每个插件的实现方式都不一样

现在的改动，核心就一句话：所有插件必须在受控的环境中运行。

- SDK 路径统一 → 插件知道自己能调什么
- 强制 describeMessageTool → 消息流转标准化
- injected runtime → 沙箱化执行，隔离风险

这套组合拳下来，插件从"自由发挥"变成了"按规矩办事"。

对开发者来说，自由度确实少了。但对用户来说，稳定性大大提升了。

这又是一个"平台思维"的典型特征：牺牲一部分灵活性，换取一致性和可靠性。

---

 改动 3：工具能力收敛

表面看：图像生成统一到 image_generate，删掉了一堆第三方 Skill 的 wrapper。

实际上：这是从"拼装"走向"内建"。

早期的 OpenClaw 很像一个乐高积木套装：核心很小，主要靠各种 Skill 插件来扩展能力。你想生成图片？装个 Skill。想做数据分析？再装个 Skill。

这种模式的好处是灵活，坏处是：

- 每个 Skill 的体验不一致
- 配置散落在各处
- 出了问题不知道找谁

现在把核心能力收进来，做成内置工具，意味着 OpenClaw 要自己承担起这些能力的稳定性和体验。

这不是在限制功能，而是在定义标准。

就像 iOS 把相机、地图这些能力内建到系统里，开发者可以直接调用，而不必自己去集成第三方。这样既保证了体验一致性，也降低了开发门槛。

---

改动 4：浏览器与执行环境安全升级

表面看：删掉 Chrome extension relay，统一用 existing-session/user session/CDP；安全方面加固了一堆东西。

实际上：这是在为"生产环境"做准备。

说实话，之前的浏览器方案确实有点"野路子"。Chrome extension relay 虽然好用，但本质上是在利用浏览器的扩展机制做一些"不那么官方"的事情。

现在全部迁移到标准的 CDP（Chrome DevTools Protocol），有几个好处：

1.更稳定：基于官方协议，不会被 Chrome 更新搞坏
2.更安全：去掉了各种注入和劫持的风险点
3.更可控：可以精确控制浏览器的行为

执行环境那一堆安全加固（禁止 JVM 注入、阻断 glibc exploit 等），更是直接把 OpenClaw 从一个"实验工具"升级成了"企业可用"的级别。

这说明什么？OpenClaw 开始认真考虑 ToB 场景了。

个人用户可能无所谓安全性，但企业用户必须考虑。这次更新，就是在告诉企业：你可以放心用了。

---

改动 5：模型配置全面升级

表面看：默认模型切到 gpt-5.4，Codex 独立出来，加了 mini/nano 版本，MiniMax 升级，还有 per-agent 的策略配置。

实际上：这是精细化运营的开始。

以前的模型配置，基本上就是"一刀切"。不管你的任务是什么，都用同一个模型、同样的参数。

现在引入 per-agent 的模型策略（thinking/reasoning/fast），意味着 OpenClaw 开始根据任务特性来匹配最优的模型配置。

- 复杂的推理任务 → 用 thinking 模式，牺牲速度换质量
- 简单的问答 → 用 fast 模式，快速响应
- 代码生成 → 走 Codex 独立通道，专门优化

这就像一个好的产品经理，不会让用户自己去纠结"该用哪个模型"，而是根据场景自动匹配最合适的方案。

另外，把 Codex 独立出来，也说明了 OpenClaw 对代码生成这个场景的重视程度。代码能力是 AI Agent 的核心竞争力之一，单独优化是明智之举。

---

改动 6：配置体系统一

表面看：删掉 .moltbot 配置，移除 CLAWDBOT_*/MOLTBOT_* 环境变量，统一为 OPENCLAW_*。

实际上：这是品牌统一和债务清理。

说实话，这次改动是最"不性感"的，但可能是最重要的。

一个项目从早期发展到成熟，往往会积累很多"历史包袱"。各种命名风格、配置方式、环境变量，都是不同时期的产物。

现在全部统一成 OPENCLAW_*，看似简单，背后传达的信息是：

> 👉 我们要做一个长期主义的产品，不能带着历史包袱上路。

这种"洁癖"式的整理，往往是产品进入新阶段的重要信号。

---

三、这次更新的深层逻辑

把这六个改动串起来，你会发现一个清晰的脉络：

阶段一：从"乱"到"治"

早期的 OpenClaw 是"生长型"的—— 有什么需求就加什么功能，怎么快怎么来。这是初创项目的常态。

现在则是"治理型"的—— 开始梳理边界、建立规则、统一标准。

这是任何一个项目从"好玩"走向"好用"的必经之路。

阶段二：从"开放"到"可控"

以前追求极致的开放性和扩展性，现在则在开放和可控之间找平衡。

ClawHub 收编插件分发、插件体系加强约束、核心能力内建，都是在建立可控的边界。

这不是变得封闭，而是负责任的开放—— 只有当平台能保证基本体验时，生态才能健康发展。

阶段三：从"框架"到"平台"

框架只负责提供能力，平台则要负责整个体验。

这次更新，OpenClaw 开始承担起更多的责任：

- 插件质量的审核责任（ClawHub）
- 核心能力的稳定责任（工具内建）
- 用户安全的保障责任（执行环境加固）
- 最佳实践的引导责任（per-agent 模型策略）

这是典型的平台化思维。

---

四、对开发者和用户意味着什么？

如果你是开发者：

短期阵痛，长期利好。

这次改动确实会带来迁移成本。插件要重写、配置要调整、代码要适配。

但适应新规则之后，你会发现：

- 用户对你的插件信任度更高了（经过 ClawHub 审核）
- 插件的稳定性更有保障了（运行环境标准化）
- 可以触达更多企业用户（安全合规达标）

如果你是用户：

体验会更稳，但自由度会降。

以后装插件可能没那么"野"了，但换来的是：

- 更少踩坑
- 更少兼容性问题
- 更一致的体验

对于普通用户来说，这是好事。对于喜欢折腾的极客来说，可能觉得有点束缚。

但话说回来，如果你真的想折腾，OpenClaw 本身还是开源的，核心代码都在那，你完全可以自己 fork 一个版本随便玩。

官方版本走平台化路线，社区版本保持开放性，这可能是最好的分工。

---

五、写在最后：OpenClaw 的野心

看完这次更新，我对 OpenClaw 的未来有了一个更清晰的判断：

它不想只做"另一个 Claude Code"或"另一个 Cursor"。

它想做的是AI Agent 时代的操作系统。

操作系统需要什么？

- 统一的应用分发渠道（ClawHub）
- 标准的应用运行环境（插件 SDK + runtime）
- 内建的核心能力（图像生成、代码执行等）
- 安全的执行隔离（浏览器 + 执行环境加固）
- 智能的资源调度（per-agent 模型策略）

这次更新，就是把"操作系统"的底座打扎实。

下一步会是什么？我大胆预测几个方向：

1.更多的核心能力内建：比如数据分析、可视化、知识库管理等
2.更强的多 Agent 协作：不同 Agent 之间可以互相调用、协同工作
3.更完善的企业级功能：权限管理、审计日志、合规认证等
4.可能的商业化探索：ClawHub 的高级插件、企业版授权等

当然，这些都是猜测。但有一点是确定的：

> 👉 OpenClaw 已经不是那个"小而美"的开源项目了。它正在成长为一个大平台。

作为观察者和使用者，我觉得这是好事。一个健康的生态，需要这样的平台来承载。

至于它能不能成功，还要看接下来的执行力。但至少，方向是对的。

让我们拭目以待。
