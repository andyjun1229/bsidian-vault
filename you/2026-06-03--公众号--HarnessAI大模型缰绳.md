上周我让 DeepSeek 帮我写个脚本，批量处理 100 个 JSON 文件。

我想着这应该很简单，5 分钟就搞定。

结果跑了 3 小时，CPU 爆满，我最后强制杀掉了进程。

我第一反应是：这个模型不行，换个更好的。

然后我换了 GPT-4，换了 Claude，都一样。

翻车方式一模一样。

那天晚上我在想一个问题：明明 2026 年的模型已经比我还聪明了，为什么连这么简单的任务都做不好？

后来我意识到：

问题不在模型，在我。

1. 我们还在用 2023 年的思维方式

回想一下 2024 年，那时候我们跟模型说话，恨不得把每句话都拆成小学生能懂的句子。

"请用非常简单的话告诉我..."、"请一步一步思考..."、"请参考以下格式..."

那时候核心问题是：

模型能不能听懂我？

到了 2025 年，模型能力上来，问题变了。它听得懂，但它不知道上下文。

于是我们开始做 RAG，做知识库，做上下文管理。

核心问题变成了：

模型不知道什么？

现在是 2026 年，模型智力在线了。

但问题又变了：

模型知道，但它不稳定。

它可能今天写得好，明天就翻车。可能处理 50 个文件没问题，到第 51 个就无限循环。

这不是智商问题，这是工程问题。

而大部分人，还在用 2023 年的思维——靠改 Prompt 解决问题。

2. 一个反直觉的真相：自由不是无限的

很多人觉得 ：

"模型那么聪明，让它自由发挥就好，为什么要加那么多框框？"

但这里有一个反直觉的真相：

自由不是无限的，自由需要边界。

没有边界的自由不是自由，是混乱。

马没有缰绳，会摔进悬崖。

车没有刹车，会冲出马路。

脚本没有熔断，会跑到天荒地老。

控制不是对立面，控制是自由的保障。

3. 大模型就像一匹马，Harness 是缰绳

你买了一匹全世界最快的马。

但它没有缰绳。

结果它跑得越快，你摔得越惨。

这就是现在 AI 工程的现状。

很多人以为缰绳是用来困住马的。

不对。

缰绳是为了让马跑得更远、更稳。

4. Harness 到底在管什么？

我的脚本跑了 3 小时那天，我在想：为什么大模型到了我这里这么蠢？

后来我明白了——

它不知道什么时候该停下。

因为我没告诉它。

8. 标杆案例：Claude Code 怎么做的？

Claude Code 是 Harness Agent 的典型实现。

收到复杂任务后，它不会直接动手，而是按固定框架执行：

探索代码库

：理清项目结构、依赖关系

制定执行计划

：拆任务、标步骤、明依赖

逐步执行并检查

：完成一步验证一步

全局检查

：做回归测试，排查遗漏

这套流程不是写在提示词里，而是 Harness 内置的。

就连高风险操作的人工确认，也是框架的"钩子"拦截实现，而非模型的"自觉"。

核心就是：把"信任模型"变成"信任框架"，模型可以犯错，框架能兜住。

9. 一个核心原则：能用代码管的，别靠"拜托"

很多人写 AGENTS.md 的时候写这样：

请记得处理完 100 个文件就停

请记得不要无限循环

然后 AI 还是跑到天荒地老。

因为"请记得"会被忘，代码不会。

正确写法：

MAX_FILES =100

defcheck_file_count(count):

ifcount > MAX_FILES:

raiseRuntimeError(f"❌ 超过限制：已处理{count}个文件，最多{MAX_FILES}个")

Hook 会执行，自然语言会被忘。

刚性约束，是对混乱的最好防御。

11. 真正的约束，是让你能走得更远

我问过自己：如果 AI 能干所有事，我要做什么？

答案是：设计它的边界。

因为边界决定了它能走多远。

没有河道的河流，会泛滥成灾

有河道的河流，能灌溉良田

约束不是在阻挡你，是在给你方向。

12. 工程师不会失业，但码农会

AI 都能写代码了，我会失业吗？

答案是：不会。

因为模型只会写代码，不会设计系统。

Harness 工程就是设计系统。

码农

工程师

写代码

设计执行环境

修一次 bug

消灭一类错误

个人能力

组织能力

码农会被替代，工程师不会。

因为工程师懂一件事：

没有约束的力量是危险的，有约束的力量才是资产。

13. 最后： Harness 不是魔法，是纪律

有了 Harness 之后，AI 写的脚本效率提高了。

不是模型变聪明了。

是它有了一套能稳定干活的系统。

Harness 本质上是一套制度。

Prompt 是一句话。

Harness 是一整套制度。

你不需要魔法。

你需要的是：

给 AI 设计一个能持续做对事情的环境。

14. 一个更深层的洞见

2026 年，我们正站在一个十字路口。

一边是对 AI 的盲目崇拜——给它自由，让它发挥。

另一边是对 AI 的恐惧——限制它，控制它。

两条路都错了。

真相是：

没有约束的发挥是混乱，过度约束的发挥是僵死。

Harness 给出的答案是第三条路——

设计边界，让力量在正确的轨道上释放。

这不仅是 AI 工程的真理。

这也是所有复杂系统运行的规律。

一句话总结

模型是马，Harness 是缰绳。

缰绳不是为了困住马，是为了让它跑得更远。

自由需要边界，力量需要约束。

控制不是对立面，控制是自由的保障。

你现在做的，是给 AI 戴缰绳，还是让它在草原上狂奔？
