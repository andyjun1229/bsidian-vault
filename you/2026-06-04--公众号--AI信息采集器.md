每天的痛苦

早上8点，我习惯性打开几个科技媒体：

36氪推送了15篇新文章

虎嗅更新了12篇

极客公园来了8篇

总共35篇文章。

理论上，这些都是高质量内容，应该对我有价值。

但现实是：

我每天只有30分钟时间浏览。

如果不筛选，我就得每篇文章分配不到1分钟——这等于没看。

如果筛选，我得扫标题、看摘要、决定点不点进去——这个过程本身就要消耗15分钟。

最后的结果通常是：看了5-6篇，真正记住的只有1-2篇。

这不是我一个人在面临的问题。这是信息爆炸时代的普遍困境。

两个方向的选择

面对这个问题，我意识到有两个方向：

方向A：用AI生成更多内容

让AI帮我写日报、写摘要、写总结——这会让信息更多，但并不会解决"读不过来"的问题。

方向B：用AI过滤内容

让AI帮我筛选、提炼、打分——减少阅读量，但提高阅读质量。

我选择了B方向。

我做了什么

用一个周末，我用DeepSeek做了一个完整的工具，叫"Tech Daily Digest"。

核心功能

1. 多源自动抓取

36氪 + 虎嗅 + 极客公园

配置RSS源，每天自动拉取最新文章。

2. 智能去重入库

每篇文章生成唯一ID（基于URL哈希）

避免重复处理同一篇文章

统一存储到本地JSON数据库

3. AI精炼（核心）

对每篇文章，DeepSeek会生成：

一句话概括

：用30字以内说明核心价值

关键要点

：提取2-3个核心观点或数据

AI相关性评分

：1-5分，判断和AI/科技的关联度

商业价值评分

：1-5分，判断商业洞察价值

推荐标记

：是否值得优先阅读

4. 日报生成

输出完整Markdown日报，包含：

目录（按评分排序）

推荐阅读（3-5篇，高分文章）

详细分类（按来源）

统计信息（AI高相关、高商业价值各有多少篇）

5. 反馈循环（这是我设计的亮点）

对感兴趣的文章，我可以运行：

node src/index.js --feedback 1,3,5

系统会对选中的文章进行

深度分析

：

核心论点是什么

引用了哪些关键数据

对行业可能产生什么影响

反映了什么趋势

对从业者有什么启发

当累积至少3篇深度分析后，还能生成

个人知识总结报告

：

本周核心主题

关键商业/技术洞察

未来6-12个月的趋势研判

给从业者的actionable建议

这才形成了真正的

个人知识库闭环

。

技术细节

批量处理，控制成本

不是每篇单独调用API，而是批量10篇一起处理。这样既提升了速度，又控制了成本。

定时任务

支持cron常驻模式，默认每天早上8点自动运行：

"schedule": { "cron": "0 8 * * *", "timezone": "Asia/Shanghai" }

数据主权

所有数据存在本地：

data/

├── articles.json # 文章库

├── feedback.json # 反馈记录

├── digests/ # 每日Markdown日报

├──

knowledge/ # 个人知识总结

完全本地化，随时可导出、备份、迁移。

关键设计决策

1. 评分体系，不是简单摘要

如果只给摘要，我还是得自己判断值不值得看。

但AI给两个评分，帮我做第一轮筛选：

AI相关性≥4

：这是我关注的领域

商业价值≥4

：这有实际价值

同时满足的，优先读。

2. 批量处理，避免成本失控

最初我试过每篇单独调用API，结果：

速度慢

成本高

容易超时

改成批量10篇一起处理后：

速度提升3倍

成本降低50%

成功率接近100%

3. 反馈循环，不是一次消费

大多数内容消费工具是"看完就丢"。

但我设计的反馈循环，让每篇有价值的内容都能沉淀：

文章 → 日报 → 深度分析 → 知识总结

这是一个持续增值的过程。

4. 完全本地化，数据主权

现在很多SaaS工具帮你管理信息，但数据在他们服务器上。

我选择全部本地化：

数据安全

可随时迁移

长期积累的价值在我自己手里
