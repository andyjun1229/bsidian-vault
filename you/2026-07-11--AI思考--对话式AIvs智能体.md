你以为会用ChatGPT就是玩转AI了？差得远。

说个真事。

上个月我审了一份60页的技术标书，用ChatGPT生成的。表面看文笔通顺、结构完整，但仔细一翻，问题一堆：

- 第5页写着"某某省公司"，第12页又写着"某某集团总部"——同一个标，甲方是谁都没统一。
- 前面说"服务对象涵盖多个在建项目"，后面又说"服务总预算约2000万元"，但这两个数据之间什么关系，没说。
- 编号从（1）到（5）都是顿号，第六条突然变成"6）"。
- 技术方案里洋洋洒洒写了三段"项目背景"，但评标专家关心的那三个评分点，一个都没突出。

你说这标书能用吗？能用。能中标吗？悬。

这就是今天大多数人用AI的真实状态：把AI当成了一个"很会说话的搜索引擎"。你问它答，你让它写它写，但你得自己盯着每一个细节，自己改模板痕迹，自己保证前后一致性。

累不累？累。

所以我今天想聊的，不是ChatGPT、豆包、DeepSeek这些"对话式AI"有多厉害——它们确实厉害，但大多数人只用了它们10%的能力。

真正的大杀器，叫"智能体"。

先搞明白一个事：对话式AI和智能体到底有什么区别？

打个比方。

对话式AI就像一个特别博学的顾问。你问它："帮我写一段标书的技术方案"，它马上给你写出来，引经据典、条理清晰。但你要自己把这段话贴到Word里，自己调整格式，自己检查有没有漏掉几个关键评分点。它只管"说"，不管"做"。

智能体不一样。智能体就像一个能自己干活的员工。

你给它一个目标："帮我把这份标书的技术方案写完，确保覆盖全部评分点，格式统一，数据前后一致。"它自己会：

1. 打开招标文件，提取评分标准
2. 打开你之前的标书模板，学习格式规范
3. 逐条撰写技术方案，每写一条对照一次评分点
4. 检查全文的数据一致性——"某某省电力公司"和"某某集团总部"不能同时出现
5. 调整格式，编号统一
6. 最后输出一个可以直接用的Word文档

全程不需要你盯着。它调用大模型来思考，调用工具来执行，调用文件系统来读写——就像一个真正的项目助理。

听懂这个区别，你就理解了为什么智能体才是AI真正的未来。

---

来，我用写标书这件事，给你拆一个实际的智能体工作流。

假设你现在要写一份"智慧园区信息化建设"的投标文件。传统做法：你打开ChatGPT，一条一条地问"帮我写项目背景"、"帮我写技术方案"、"帮我写人员配置"……然后一条一条地复制粘贴，拼成一个文件。

智能体的做法：

第一步，你告诉它："我要投一个智慧园区项目，标书在 /标书/招标文件.pdf，模板在 /标书/模板.docx，帮我出一份完整的投标文件。"

第二步，智能体自动启动一个工作流：

工作流：写标书
├── 步骤1：读取招标文件，提取评分标准和硬性要求
├── 步骤2：读取模板文件，学习格式和风格
├── 步骤3：生成项目概述（对照评分点1-3）
├── 步骤4：生成技术方案（对照评分点4-8）
├── 步骤5：生成人员配置方案（对照评分点9-10）
├── 步骤6：全文一致性检查（专有名词、数据、编号）
├── 步骤7：输出为Word文档，保存到桌面
└── 步骤8：通知你"标书已完成，请检查"

每一步之间，智能体会自动传递上下文。第3步生成的"项目概述"，第4步的技术方案会引用它来保持一致性。第6步的校验环节，会逐条检查全文有没有写错甲方名字、有没有漏掉评分点。

第三步，你打开文件，确认无误，直接投。

看到区别了吗？

- 对话式AI：你指挥每一步，自己拼装
- 智能体：你给目标，它自己拆解、执行、交付

一个像工地上的包工头——每天追着工人问进度。一个像项目经理——你把活扔给他，到点来验收就行。

如果你也想配置自己的智能体，目前最主流的三个终端智能体，我来分别说一下怎么搞。

---

先说 Claude Code（Anthropic 出品的）。

安装很简单：

npm install -g @anthropic-ai/claude-code

然后运行 claude，浏览器登录你的 Anthropic 账号，完事。

它怎么工作？你要改一段代码、写一个功能，直接告诉它：

claude -p "帮我把这个项目的 README 改好，加安装说明和API文档" --allowedTools "Read,Edit"

-p 的意思是"一次搞定退出来"，--allowedTools 限制它能干什么（读文件、写文件）。

它还能读你项目根目录下的 CLAUDE.md 文件——那是你的"项目说明书"。你在里面写好项目架构、编码规范、常用命令，它每次工作都会照做。比如：

# 项目规范
- Python 3.11，FastAPI 框架
- 代码用 ruff 检查，pytest 测试
- API 文档自动生成到 /docs

你第一次配置好 CLAUDE.md，以后所有任务它自动遵守这些规则。不需要你每次重复说。

---

再说 OpenClaw（开源、支持任意大模型）。

安装：

npm i -g opencode-ai@latest

配好 API key（它支持 OpenRouter、Anthropic、OpenAI 等等），然后同样一句话：

opencode run "帮我把配置文件里的敏感信息提取到 .env 里，别留硬编码"

它有一个 -f 参数可以把上下文文件带进去：

opencode run "审查这个配置文件有没有安全问题" -f config.yaml -f .env.example

OpenClaw 的好处是它不绑定某个大模型——你想用 DeepSeek、Claude、GPT 都行，在配置里换模型就行。

---

最后说 Hermes Agent——也就是我现在这个。它是我最熟悉的，也是今天给你做了这么多事的那个。

安装：

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

然后运行 hermes，选一个模型供应商（DeepSeek、OpenRouter、Anthropic 任选），配好 API key，就能用了。

Hermes 跟前面两个最大的区别，是它有一个技能系统——它可以记住"怎么做一件事"，下次你再做同样的事它自动就会了。

举个例子，今天下午你给我一篇炒股的文章，我帮你润色、改格式、配图。如果我把这个流程存成"公众号文章优化"技能，以后你再说"帮我优化一篇公众号文章"，我直接全套流程跑完，不用你再教。

另外 Hermes 能接 Telegram、Discord、微信——你不在电脑前的时候，手机上也能让它干活。

---

三者的选择很简单：

- 如果你主要写代码：Claude Code 最顺手，安装即用，社区最大
- 如果你想要开源、不绑定某家公司：OpenClaw，想用什么模型随你挑
- 如果你想干的不只是写代码——写文章、整理资料、做配图、定时任务、跨平台使用：Hermes Agent 能力最全

不管你选哪个，配置核心就三步：

1. 安装 + 配 API key（每家官网都有教程，5分钟搞定）
2. 告诉它你的项目规则（CLAUDE.md 或类似的配置文件）
3. 给它第一个任务试试，不对就让它改——它记住偏好后会越来越好用

三套工具，门槛都一样低。区别只在于你选哪个搭档。
