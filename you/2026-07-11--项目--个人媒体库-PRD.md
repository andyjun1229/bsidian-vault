# 个人媒体库系统 — 产品需求说明书 (PRD)

**版本**: v1.1（国内适配版）  
**日期**: 2026-06-29  
**作者**: 基于个人痛点分析  
**目标用户**: 个人开发者 / 安卓手机 + Mac 用户，照片视频 5000+/400+

tags: [项目]
---

## 1. 痛点总结

| # | 痛点 | 频次 | 严重程度 |
|---|------|------|----------|
| P1 | 手机存储不断被照片视频吃满（512G 已用超半，已手动清理过一半） | 持续 | 🔴 高 |
| P2 | 云存储（Google Photos / 百度网盘等）资费贵 + 隐私泄露风险 | 持续 | 🔴 高 |
| P3 | 换手机时数据迁移痛苦 | 每 2-3 年 | 🟡 中 |
| P4 | 转移到电脑后，想翻看历史照片很不方便 | 持续 | 🔴 高 |

**核心矛盾**: 本地存 = 占手机空间。云存 = 花钱 + 隐私 + 迁移难。存电脑 = 查不了。

---

## 2. 方案定位

**一句话**: 把 Mac 变成你的私人媒体服务器，手机自动同步到 Mac，Mac 上通过 Web 随时随地查看。

**关键设计原则**:
- **零月费** — 只用已有硬件（你的 Mac），不新增任何付费云服务
- **隐私优先** — 数据全部存在本地，不经过任何第三方服务器
- **手机瘦身** — 操作完成后手机端可以安全删除原片，释放空间
- **随时随地可查** — Mac 不开屏幕也能通过 Web 或 App 查看
- **换机无忧** — 数据全在 Mac 上，新手机只需安装同步 App 即可

## 4. 核心功能需求

### 4.1 自动同步 (手机 → Mac)

| 需求 | 优先级 | 说明 |
|------|--------|------|
| 新照片/视频自动同步到 Mac | P0 | 后台运行，无需手动操作 |
| WiFi 环境下自动同步，移动数据不传 | P0 | 避免消耗流量 |
| 增量同步 — 只传新增的，不重复传 | P0 | 首次全量之后每次几秒 |
| 同步完成后可选删除手机原片 | P1 | 释放手机空间 |
| Live Photo / 动态照片完整保留 | P1 | 安卓端的 Motion Photo |

**⚠️ 国内适配说明**: FolderSync Pro / PhotoSync 均在 Google Play 发布，国内无法直接购买下载。以下两个方案均为国内可用路线。

---

#### 路线 A（主推）: Syncthing + Syncthing Android App

**原理**: Syncthing 是纯 P2P 同步工具，安卓和 Mac 各装一个，互相直连，不需要任何中间服务器。

| 项目 | 说明 |
|------|------|
| 费用 | **¥0**，完全开源 |
| 安卓端 | 从 [syncthing.net](https://syncthing.net) 下载 APK，或 F-Droid 下载，国内直接装 |
| Mac 端 | `brew install syncthing` 一键安装 |
| 后台同步 | ✅ 安卓端有系统级 Watchdog，拍照后自动同步 |
| WiFi 限制 | ✅ 可设置在充电+WiFi 时同步，移动数据不走 |
| 同步后删除 | ✅ 安卓端可配置"删除远端文件时的行为" |
| 上手难度 | 中等（首次配对需要二维码扫码连接） |
| 隐私 | ✅ 端到端加密，不经过任何服务器 |
| 国内可用性 | ✅ 纯开源，无墙问题 |

**Mac 端部署**: `brew install syncthing && brew services start syncthing` 后台常驻。

---

#### 路线 B（备选）: CX 文件管理器 + Mac SMB 共享

**原理**: Mac 开启 SMB 文件共享（系统自带），安卓端用 CX 文件管理器（酷安/各大应用市场可下）挂载 SMB 目录，手动或定时复制。

| 项目 | 说明 |
|------|------|
| 费用 | **¥0**，CX 管理器免费 |
| 安卓端 | 酷安/华为商店/小米商店直接搜"CX 文件管理器"下载 |
| Mac 端 | 系统偏好设置 → 共享 → 文件共享 ✅ 零安装 |
| 自动同步 | ⚠️ **不支持真正的后台自动**，需要打开 App 手动操作或设置定时任务 |
| 适用场景 | 偶尔手动备份，或首次批量导入 |
| 上手难度 | **低**，不需要装任何额外软件 |

#### 路线对比总结

| 对比项 | Syncthing (路线A) | CX+SMB (路线B) |
|--------|-------------------|-----------------|
| 费用 | ¥0 | ¥0 |
| 国内下载 | ✅ 官网 APK 直装 | ✅ 各大应用商店 |
| 自动后台同步 | ✅ 拍照即同步 | ❌ 需手动操作 |
| Mac 端 | 需装 Syncthing | 系统自带 SMB |
| 上手难度 | ⭐⭐⭐ 中等 | ⭐ 最简单 |
| 长期推荐 | ⭐⭐⭐⭐⭐ **主推** | ⭐⭐⭐ 过渡方案 |

**推荐**: 先用 **路线 B（CX+SMB）** 做首次全量导入（1小时搞定），再装 **路线 A（Syncthing）** 做日常自动同步。这样既不用等，后续也不用操心。

### 4.3 远程浏览 (随时随地查看)

这是解决"存电脑后怎么看"的核心模块。

| 需求 | 优先级 | 说明 |
|------|--------|------|
| Web 界面浏览照片和视频 | P0 | 任何设备浏览器打开即可 |
| 按时间线滚动 | P0 | 类似 Google Photos 的时间轴 |
| 相册/标签管理 | P1 | 创建自定义相册 |
| 视频在线播放 | P1 | H.264/H.265 流式播放 |
| 人脸识别分组 | P2 | 按人物自动归类 |
| 地图模式 | P2 | 带 GPS 的照片在地图上展示 |
| 分享链接 (临时) | P2 | 生成可分享的单张/批量链接 |

**方案选型: Immich** (强烈推荐)

| 对比项 | Immich | Photoview | Piro | 自己写 Flask |
|--------|--------|-----------|------|-------------|
| 费用 | 免费开源 | 免费开源 | 免费开源 | 开发时间 |
| Web 时间线 | ✅ 媲美 Google Photos | ✅ | ✅ | 需从头开发 |
| 视频播放 | ✅ | ✅ | ✅ | 复杂 |
| 人脸识别 | ✅ | ❌ | ❌ | 极复杂 |
| 地图 | ✅ | ❌ | ❌ | 极复杂 |
| 移动 App | ✅ 官方 App | ❌ | ❌ | 需开发 |
| Docker 部署 | ✅ 推荐 | ✅ | ✅ | 不适用 |
| 推荐度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ | ❌ |

**为什么是 Immich**:
- 功能最接近 Google Photos 的开源自部署方案
- 有原生移动 App（安卓/iOS），可以直接在手机上查看
- 支持自动备份功能（如果你愿意的话也可以当双保险）
- 活跃社区，持续更新
- 即使不装 App，通过浏览器也能访问

**运行方式**: Mac 上通过 Docker Desktop 运行 Immich（仅浏览时启动，或设置为 Mac 不休眠时持续运行）。

### 4.4 远程访问 (出门在外也能看)

| 需求 | 优先级 | 说明 |
|------|--------|------|
| 外网访问 Immich Web | P0 | 不在家也能看 |
| 安全性 — 不暴露公网端口 | P0 | 不把服务直接挂到公网 |
| 不需要固定公网 IP | P1 | 家庭宽带无公网 IP 也能用 |

**推荐方案: Tailscale (免费版)**

- 在你的 Mac 和手机上都装 Tailscale
- Mac 和手机组成加密虚拟局域网
- 出门在外，手机通过 Tailscale 连回 Mac 的 Immich
- 免费版支持 3 台设备，够用
- 无需公网 IP，无需端口映射，端到端加密

**备选: Cloudflare Tunnel** — 不需要装客户端，但需要有个域名。不建议新手选这个。

### 4.5 换机迁移 (MX 手机迁移较特殊，后面再说)

这是这个方案的**隐藏优势**:

- 旧手机全部照片已在 Mac
- 新手机安装 Syncthing + Tailscale
- 如果新手机也需要本地有一份: Syncthing 反向同步 Mac → 新手机
- 如果不需本地存: 直接通过 Immich 远程查看
- 换机时间: **从原来的"折腾一整天"缩到"装 2 个 App"**

## 5. 实施路线图

### Phase 1 (1-2 天) — 基础同步 + 浏览 ✅ 立即能做

1. **Mac 端**: 创建 Media 目录结构
2. **Mac 端**: 开启 SMB 文件共享（系统偏好设置 → 共享 → 文件共享）
3. **安卓端 → 首次全量导入**: 安装 CX 文件管理器 → SMB 挂载 Mac 共享目录 → 把 DCIM/Camera 复制过去（批量操作，1-2 小时）
4. **Mac 端**: `brew install syncthing && brew services start syncthing` 常驻后台
5. **安卓端 → 日常同步**: 从 syncthing.net 下载 APK 安装 → 扫码配对 Mac → 设置 DCIM/Camera 目录为共享文件夹 → 配置"仅 WiFi + 充电时同步"
6. **部署 Immich**: Docker Desktop 跑 Immich
   - 导入已有 Media 目录
   - 浏览器访问 `http://Mac本地IP:2283`

**Phase 1 交付物**: 手机照片自动同步到 Mac，Mac 上浏览器可浏览

### Phase 2 (1 天) — 远程访问

1. Mac 和手机安装 **Tailscale**
   - Mac: `brew install tailscale && tailscale up`
   - 安卓: 从官网或酷安下载 Tailscale APK
2. 两台设备登录同一 Tailscale 账号
3. 手机通过 Tailscale 分配的 IP 访问 Immich（如 `http://100.x.x.x:2283`）
4. 验证外网（4G/5G）下可正常加载缩略图和播放视频

**Phase 2 交付物**: 出门在外也能用手机查看 Mac 上的全部照片

### Phase 3 (可选) — 进阶功能

1. Immich 人脸识别（需 Mac 有一定性能，第一次全量识别较慢）
2. 外部存储 / 定时备份到移动硬盘
3. 自动微信图片导入（微信电脑版备份目录）
4. Screenshots 清理与归档

## 7. 风险与应对

| 风险 | 可能性 | 应对方案 |
|------|--------|----------|
| Mac 不在线时无法查看 | 中（出门 Mac 可能关机） | 长期建议留一台低功耗设备；短期接受"不在家时不可查看" |
| 首次同步耗时久 | 中（几千文件走 WiFi） | 利用夜间睡眠时间同步，CX+SMB 批量传最快 |
| Docker 对 Mac 性能影响 | 低 | Immich 空闲时占用很小；不需要时停掉容器 |
| 某一天硬盘坏了 | 低-中 | 定期备份到移动硬盘（建议每季度一次，接上 Mac 跑 rsync） |
| 安卓端 Motion Photo 兼容性 | 低 | Syncthing 传原始文件，不修改格式；Immich 后续适配 |
| Tailscale 在国内的连接稳定性 | 低-中 | Tailscale 基于 WireGuard，国内大多数网络可用；备用方案: frp 或 ZeroTier |

## 8. 与非技术用户对比

如果是家里老人/非技术用户，我会推荐 **Google Photos 付费版**（$1.99/月 100GB 或 $9.99/月 2TB），因为开箱即用、零配置、自动备份全平台。

这套方案的优势在于:
- **¥30 一次性 vs 云服务每年 ¥120+**
- **数据完全掌握在自己手里**
- **换机零摩擦**
- 适合有动手能力的人
