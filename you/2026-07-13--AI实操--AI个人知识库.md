# AI个人知识库

## 一句话定义
AI个人知识库是一种「加工系统优先」的知识管理范式——由Karpathy提出并实践的以raw/wiki/outputs三层架构为核心的AI原生知识库，核心颠覆在于：不花时间整理底层（raw是「垃圾堆」），让AI自动在上层为你编译出可用知识。

## 核心要点
- **存储系统 vs 加工系统**：传统笔记软件（Evernote/Notion）本质是「存储系统」——你花大量时间整理标签分类，但笔记越多越难用；AI个人知识库是「加工系统」——只管往里扔素材（raw/），AI帮你整理和使用（wiki/ + outputs/）。
- **操作系统「虚拟内存」式设计**：底层可以乱得像垃圾堆，但上层给你一个整齐的维基。越不管底层，上层越好用。
- **关键公式**：「问1000个好问题 > 存1000条笔记」——知识不是存出来的，是用出来的。
- **从「存」到「用」的转变**：Evernote本质是更好的存储柜——你往里塞东西，它帮你存着；AI知识库是工厂——AI从仓库取材料，加工成你能用的东西。
- **文件系统级可移植性**：不用任何特定软件（VS Code/Obsidian/记事本都行），AI只关心文件在哪里。迁移成本几乎为零。
- **AI图书管理员模式**：通过CLAUDE.md（schema文件）告诉AI知识库的规则、结构、优先级，AI自动执行编译。

## 方法 / 步骤

### Karpathy式搭建（30分钟）
1. 建目录结构：`my-knowledge-base/` 下的 `raw/` `wiki/` `outputs/`
2. 写CLAUDE.md：定义角色、规则、优先级（参考模板见下方）
3. 往raw/扔素材——不整理、不重命名、不分类
4. 给AI指令：「读取raw/中的所有内容。按规则在wiki/中编译。创建INDEX.md，为每个主要主题创建.md文件。链接相关主题。」
5. 开始提问：「基于wiki/中的所有内容，我对【主题】理解中最大的三个空白是什么？」

### CLAUDE.md 核心模板
```
raw/ 是源材料，永远别动
wiki/ 是AI整理的地方，完全由AI维护
outputs/ 是生成的报告和答案
每个主题在wiki/有自己的.md文件
用[[topic-name]]格式链接相关主题
```

### 日常使用工作流
1. 随手扔素材到raw/（文章、截图、会议记录、项目文档、书签）
2. AI自动读、理解、挂载到wiki知识网络
3. 对wiki提问获得加工后的答案
4. 把outputs放到outputs/，或让AI用新见解更新wiki/
5. 正循环：每个问题让下一个答案更好

## 应用场景
- **主题写作**：从散落笔记中自动生成系统性文章
- **经验复盘**：每写一条笔记，AI自动挂载到已有知识网络
- **投资研究**：积累的行业笔记被AI整理成完整分析框架
- **学术研究**：论文笔记自动分类和关联，生成文献综述框架
- **长期知识积累**：今天处理100条，明天1000条，下个月1万条——知识库自我进化

## 常见误区 / 边界
- 误区：AI知识库 = 会搜索的聊天记录
  - 正解：AI知识库是持续「编译」的系统，不是一次性问答
- 误区：需要把raw/整理干净才能用
  - 正解：Karpathy方法的核心就是「不整理」——底层越乱，上层越简单
- 误区：需要特定软件才能搭建
  - 正解：只需要文件夹和md文件，任何编辑器+AI都能用
- 边界：需要AI智能体能力（Claude Code / OpenClaw / Hermes等）来执行编译
- 边界：需要学会「提问」——问问题比存笔记需要更高的认知成本
- 边界：不适合喜欢精雕细琢笔记的用户——raw/像垃圾堆会让人受不了
