# AI知识库构建法

## 一句话定义
AI知识库构建法是用AI智能体将零散的个人笔记激活为结构化知识网络的系统性方法，核心是"raw原始记录 → wiki知识条目 → output系统性输出"三层架构，配合AI图书管理员（claude.md工作手册）自动处理。

## 核心要点
- **三层架构**：raw（原始记录，只存不改）→ wiki（AI加工为可检索知识条目）→ output（通过双向链接串起来的系统性输出）
- **理解>分类**：传统标签系统只"记住"笔记在哪，AI要"理解"笔记之间的隐含关系
- **AI图书管理员**：核心不是文件夹架构，而是给AI的工作手册（claude.md），告诉它你要什么结构、格式、优先级
- **知识激活**：知识库不是帮你"找"知识，而是让知识在需要的时刻"跳出来"
- **自动进化**：AI自动去重、更新、提炼重复观点为原则、关联孤立笔记
- **三个痛点**：记了不知道为什么记、灵感是孤岛无法串联、零散知识难以调用

## 方法 / 步骤

### 第一步：搭建三层目录结构
```
raw/      → 原始笔记，随便记（md/txt/pdf），像仓库——只管扔进去
wiki/     → AI加工后的结构化知识条目，像图书馆编目系统
output/   → 系统性输出，所有wiki通过双向链接串联，像维基百科
CLAUDE.md → 给AI的工作手册，定义规则和优先级
```

### 第二步：配置AI图书管理员（claude.md）
在Obsidian根目录创建claude.md，定义AI的角色和规则，关键原则：
1. **理解 > 分类**：找出隐含连接——这条笔记和哪条呼应？这个观点在更大体系里扮演什么角色？
2. **自动优化**：去重、标注历史版本、提炼重复出现的原则
3. **自我进化**：每次新增笔记后重新评估相关条目
4. **随时激活**：用户不应该"找"知识，应该被知识"找到"

### 第三步：给AI第一个指令
"帮我根据 claude.md 的规则，整理我的笔记库"
- 第一次运行：5-10分钟（取决于笔记数量）
- 之后每次新增笔记：只需"更新知识库"

### 第四步：持续喂养
- 随手记，不需要考虑分类
- AI会自动读取、理解、挂载到知识网络
- 发现重复自动合并，发现过时标记历史版本，发现反复出现的观点提炼为核心原则

### 直接可用的claude.md模板
包含：你是谁（AI图书管理员）、工作原则（理解>分类/自动优化/自我进化/随时激活）、工作流程（扫描理解→识别概念→创建/更新wiki条目→优化合并→生成系统性输出）、自动化规则（增量更新/智能去重/活跃度追踪/质量评分）、用户交互模式（查询概念/新增笔记/定期复盘）

## 为什么AI知识库不一样

**传统笔记法的痛点：**
- 搜关键词找到5条笔记，时间跨度4年，但记不清逻辑关系
- 灵感是孤岛，隔几个月就忘了
- 拼凑式写作，内容散、碎、没体系

**AI知识库的差异：**
- 搜"AI算力"出来的不是一堆笔记复制粘贴，是一个完整结构（历史→技术趋势→行业格局→风险）
- AI看到笔记之间的隐含关系——光模块的技术分析是算力需求的逻辑延伸，800G的升级是行业竞争的必然结果
- 把你两年前的孤立观点放到更宏大的逻辑里，从"孤立的灵感"变成"体系的一环"

## 应用场景（内容创作视角）
- 主题写作：从散落笔记中自动生成系统性文章，2小时完成（传统4小时还不一定出得来）
- 经验复盘：每写一条笔记，AI自动挂载到已有知识网络
- 投资研究：积累的行业笔记被AI整理成完整分析框架
- 学术研究：论文笔记自动分类和关联，生成文献综述框架

## 理想中的终极知识库
- 你只需要记录（读书笔记、聊天记录、会议纪要、突然的想法）
- AI自动读、自动理解、自动挂载到知识网络
- AI自动去重、标记历史版本、提炼原则
- 知识库自我进化——今天处理100条，明天1000条，下个月1万条
- 你不是在存"仓库的存货"，而是在喂养一个会成长的思维伙伴

## 常见误区 / 边界
- 误区：知识库就是文件夹分类
  - 正解：核心不是三个文件夹的结构，而是那个工作手册（claude.md）。不是AI帮你干活，是你得教AI怎么干活
- 误区：有标签系统就够了
  - 正解：标签能帮你"找到"所有海边的照片，但AI能帮你发现"三张照片其实是一段连续的故事"
- 误区：知识库是一次性搭建的
  - 正解：知识库需要持续喂养，你喂得越多它越聪明
- 边界：需要AI智能体支持（Claude Code / OpenClaw / Hermes等）
- 边界：首次搭建需要5-10分钟，后续增量更新即可
