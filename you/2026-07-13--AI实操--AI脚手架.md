# AI脚手架

## 一句话定义
AI脚手架是让模型从"会说"变成"会做"的最小基础设施组合（模型、API、IDE/CLI、执行环境、反馈回路）。

## 核心要点
- 没有脚手架，AI只能停留在聊天层。
- 脚手架搭好后，AI才能进入真实任务执行。
- 跨过配置门槛后，效率提升往往是非线性的。
- 搭建脚手架是深度使用AI的第一道门槛，而非理解能力。
- 工具链就像给AI装上了手脚，让它从能说话变成能做事。
- **使用脚手架不是更方便，而是完全不同的使用模式。**
- **第一道分水岭不是理解能力，是搭建能力。** 很多人问"为什么不直接用免费的AI？"，但免费聊天框没有手脚——能让AI写函数，但没法让它连工具、跑代码、操作文件。
- **好的脚手架能成长：** 从体力活助理→经验库提取器→初步方案生成器→专业智能体。不是一步到位，是逐步积累AI对你的理解。

## 三大主流智能体工具对比

| 维度 | Claude Code | OpenClaw（龙虾） | Hermes Agent |
|------|------------|-----------------|-------------|
| 适合场景 | 写代码最强 | 自定义程度高 | 不想折腾智能体本身 |
| 安装方式 | `npm install -g @anthropic-ai/claude-code` | 配API key + 本地部署 | `curl -fsSL https://hermes-agent.nousresearch.com/install.sh \| bash` |
| 核心特性 | CLAUDE.md配置文件，项目说明书，自动遵守规则 | 开源、支持任意大模型、可绑定飞书等消息平台 | 技能系统（Skill），记住"怎么做一件事" |
| 门槛 | 需要付费和订阅 | 需要技术背景部署 | 配置最简 |
| 推荐场景 | 开发、写代码 | 喜欢折腾、要远程控制、特定场景（如文件在家电脑上） | 不想投入精力维护智能体本身 |

### 三方快速选择
- 主要写代码：**Claude Code**最强
- 喜欢折腾、要开源可定制：**OpenClaw**
- 不想花太多精力折腾智能体本身：**Hermes Agent**

### 通用的三步配置法
1. 安装 + 配API key（各家官网都有教程，5分钟搞定）
2. 告诉AI你希望它成为的角色或任务规则（CLAUDE.md / SOUL.md 或类似配置文件）
3. 给第一个任务试试，不对就让AI改——它记住后会自动优化

## 方法 / 步骤（可选）
1. 选择可执行环境（CLI或IDE插件）。
2. 配置稳定模型与API。
3. 打通文件读写、命令执行与测试反馈。
4. 把流程固化为个人SOP。
5. 跨过配置门槛（IDE、插件、API KEY）。
6. **技巧**：如果担心AI回答不准确，把官方配置文档扔给它，让它先学习，再教你怎么做。

## 脚手架搭建的常见门槛
- **付费门槛**：好的智能体要么官方账号付费，要么API KEY付费。免费版限流、额度不够、配置问题一堆。
- **配置门槛**：配置IDE、装插件、买API KEY——这些步骤听起来麻烦，但必须跨过去。
- **认知门槛**：不是"这个工具很强"，是"你想做这件事，用这个就行"。先看场景再选工具。

## 应用场景（面向内容创作）
- 自动化整理素材、重写多平台版本。
- 生成内容脚本并做快速迭代。
- 程序开发、调试问题、设计系统。
- **AI写标书**：用智能体读完整Word文档，处理格式检查、填充、校对（详见[[AI写标书]]）
- **知识库构建**：配合raw/wiki/output结构，AI图书管理员自动处理（详见[[AI知识库构建法]]）

## 常见误区 / 边界
- 误区：免费聊天版就能承担工程化任务。
- 误区：把"懂概念"误当"能落地"。
- 误区：有脚手架的AI只是更方便的聊天。
- **误区：以为会对话式AI就是玩转AI了。** 对话式AI是锤子，智能体是工具箱。
- **误区：好智能体的门槛很高。** 三大工具的安装+配置都只需5-10分钟。
- 边界：需要一定的技术背景（IT工程师更容易搭建）。
- 边界：需要付费（官方账号或API KEY），免费版本行不通。
- 边界：智能体需要时间"培养"，不是一步到位的。
