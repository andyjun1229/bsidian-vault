# Skill设计法则

## 一句话定义
Skill是Agent可复用的能力模块，其本质不是提示词模板，而是"可执行的程序"——有输入、有输出、有检查点、有异常处理、有优先级规则。

## 核心要点
- **Skill ≠ 知识库 ≠ 提示词模板**：顶级Skill是一个可执行的程序，不是告诉AI"做什么"，而是"构建一个让AI无法做错的系统"
- **Skill = 专业知识 + 对AI行为的精确控制 + 可复用的工作系统**
- **微软研究三真相**（arXiv 2605.23899）：更好的执行器不一定是更好的提取器；读起来越好的Skill往往表现越差；Skill不是附加插件而是操作系统
- **Skill消费是"重塑默认策略"**，不是"加载一个工具"——同一份Skill在不同模型上被解释成完全不同的行为模式

## 花叔Skill设计哲学
1. **"AI是实习生，不是专家"**：给AI具体身份和关系定位，而非泛泛的"你是一个助手"
2. **"默认值是陷阱"**：明确告诉AI不要做什么，比告诉它做什么更重要。AI的默认输出是训练语料的"最大公约数"
3. **"流程即产品"**：Skill不是知识库，是可执行的程序 — 10步标准流程 + 4个检查点 + 异常处理表

## Skill写作的5层架构模型
基于huashu-design分析，Skill写作可分为5层：

```
Layer 5: 触发层 (Trigger) — 什么时候加载这个Skill？穷尽触发词
Layer 4: 角色层 (Persona) — AI应该扮演谁？和谁的关系是什么？
Layer 3: 原则层 (Principles) — 不可违反的核心规则（按优先级排序）
Layer 2: 流程层 (Workflow) — 具体怎么做？步骤、检查点、异常处理
Layer 1: 资源层 (Assets) — 组件、模板、参考文档、脚本工具
```

### Layer 5: 触发层
- 在description里穷尽触发词（用户可能用的所有表达方式）
- 区分主干触发词和边缘触发词
- 明确不适用场景

### Layer 4: 角色层
- 身份 + 关系 + 能力边界 + 动态角色
- 公式："你是一位[具体身份]，不是[容易混淆的身份]。用户是你的[关系]。"

### Layer 3: 原则层
- 原则必须有编号和优先级
- 每条原则配触发条件
- 每条原则配反例（真实踩过的坑）
- 反例写法非常有效：场景 → 错误做法 → 后果 → 正确做法

### Layer 2: 流程层
- 标准流程：10步流程 + 4个检查点
- 每个步骤配：具体动作（不是模糊建议）、检查点（停下等用户确认）、异常处理（如果X发生做Y）
- 8阶段Fallback模式
- 异常处理表

### Layer 1: 资源层
- 可复用的组件（代码片段）
- 标准化的文档格式（模板）
- 知识库和最佳实践（参考文档）
- 自动化脚本（工具）

## 从需求到Skill的7步法则
1. **定义领域边界**：解决什么问题？不解决什么？用户在什么场景需要它？
2. **给AI职业身份**：身份 + 关系 + 能力边界 + 动态角色
3. **提炼核心原则**：3-7条不可违反的原则，按优先级排序。来源：真实踩的坑、行业最佳实践、对AI弱点的认知
4. **设计工作流程**：把心智模型变成可执行的步骤，每步骤有输入、输出、检查点
5. **预设异常处理**：需求模糊、技术难题、用户反馈不好、超出能力等情况的预案
6. **准备资源库**：组件、模板、参考、工具
7. **写触发词和描述**：能力概述 + 触发词列表 + 主干能力 + Fallback机制 + 可选功能

## 微软研究的三个反直觉真相

### 真相一：更好的执行器 ≠ 更好的提取器
- Skill提取和任务执行是两种不同的能力
- 执行器要"完成任务"，提取器要"把完成过程翻译成别人能看懂的说明书"
- 选择提取器 ≠ 选择最强模型

### 真相二：读起来越好的Skill，往往表现越差
- GPT-5.4当评委判断Skill质量，准确率仅46.4%（跟随机扔硬币没区别）
- 当两个Skill真实性能差距超过5%时，评委反而选对了只有15.8%
- 人类直觉倾向于"流畅、完整、逻辑清晰"，但这些跟"能解决问题"不是一回事
- **真正有用的只有三个维度**：失败机制编码、可执行具体性、高风险动作黑名单
- 通用建议（清晰度、完整性、逻辑结构）反而会降低性能

### 真相三：Skill不是附加插件，而是操作系统
- 同一Skill在不同模型上效果天差地别（GPT-5.4上-2.0%，Qwen3.5-35B上+9.5%）
- 因为Skill消费是"重塑默认策略"，不同模型的默认策略不同
- Skill适配是每目标属性——不要期望一个Skill能在所有模型上工作

## 经验池陷阱
- 不同领域的"有用经验"不同：表格任务偏向成功轨迹，具身规划任务中失败轨迹也有价值
- 全失败的池始终最差 —— 成功轨迹提供"怎么走"，失败轨迹提供"别走哪"
- 只有知道"怎么走"才能真正前进

## 花叔的四个底层能力
1. **领域深度**：对设计哲学有深入理解，能写出有品位的约束
2. **对AI弱点的认知**：知道AI会凭记忆做断言、产出AI slop、闷头做到底
3. **迭代思维**：每个版本都基于真实踩坑升级
4. **量化思维**：用数字让原则可执行（"成本对比：WebSearch 10秒 << 返工 2小时"）

## 常见误区/边界
- 误区：Skill写得越详细越好 → 正确：通用建议反而降低性能，要的是具体补救措施
- 误区：一个Skill能通吃所有模型 → 正确：Skill适配是每目标属性
- 误区：经验越多越好 → 正确：经验池构成需要精心设计，不同领域策略不同
- 误区：Skill是知识库 → 正确：Skill是可执行的程序，有检查点和异常处理
