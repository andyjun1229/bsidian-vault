# 操作日志：AI智能体考官模式考核记录

## 背景
用学习法中第3步"AI当考官"模式考核自己对"AI智能体"的理解。目标不是测试分数，是暴露盲区。

## 考点深度拆解：Agent框架 vs 大模型 vs 工具的关系

这个考点在考核中暴露了概念模糊，值得单独记下来。

### 核心结论
**Agent框架 ≠ 大模型。大模型是Agent框架里的一个推理引擎。**

### 三层架构
| 层级 | 角色 | 做什么 |
|------|------|--------|
| **大模型（LLM）** | 大脑/推理引擎 | "思考"——理解用户意图、决定用什么工具、分析返回结果 |
| **Agent框架** | 循环调度器 + 消息路由器 | ①把用户指令+工具列表+上下文打包发给LLM
②把LLM返回的"工具调用指令"路由到具体工具执行
③把工具执行结果喂回LLM，让LLM决定下一步 |
| **工具（Tools）** | 手脚 | 实际干活——调API、读文件、执行命令 |

### 类比
大模型 = 大脑（思考"做什么"）
Agent框架 = 神经系统（把大脑指令传给手脚）
工具 = 手脚（实际干活）
用户 = 老板（给出目标）

### ReAct循环的具体过程
```
用户指令 → Agent框架打包发给LLM → LLM"思考"返回工具调用指令
         → Agent框架执行工具 → 结果喂回LLM → LLM再次"思考"
         → 循环直到LLM返回"最终答案" → Agent框架输出给用户
```

### 为什么Skill有效？
装Skill = 在发给LLM的上下文里附加了专业指令。LLM的"思考"基于增强版上下文，所以决策质量不同。不是Agent框架变强了，是LLM收到的"考前小抄"变厚了。

## 答对的
1. ✅ Agent和普通AI对话的本质区别——Agent能直接完成操作任务
2. ✅ Agent需要工具调用能力（MCP、API集成）
3. ✅ Agent需要记忆系统保存用户反馈

## 暴露的盲区（需补课）
1. ❌ **数据处理层** — Agent拿到原始API数据，需要结构化和清洗才能用（字段名映射、空值处理、格式统一），不是直接丢给大模型
2. ❌ **状态管理** — 多步骤任务的执行上下文（Task State / Session State），不等同于记忆
3. ❌ **Skill的结构化设计** — 被AI代劳做Skill，没自己拆过结构
4. ❌ **ReAct循环** — Agent收到任务后的完整决策循环：思考→行动→观察→再思考→再行动，循环直到完成。这是Agent区别于单次大模型调用的根本特征
