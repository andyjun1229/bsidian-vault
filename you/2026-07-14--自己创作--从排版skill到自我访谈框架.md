# 从排版skill到自我访谈框架：一个逆向分析的故事

- [[raw/2026-02-27--公众号--OpenClaw-Obsidian-CC知识管理三件套.md]] — 同为摸鱼小李的作品，OpenClaw+Obsidian+CC 三件套的安装和技能体系

**当时背景：** 日更公众号「飞叔AI沉思录」，刚装好 gzh-design 排版 skill，逆向分析后发现其设计哲学可以复用。同时正用 AI 做自我访谈框架，发现自己的 skill 只是一个提示词，不是一个系统。

---

之前写的那篇用AI做自我认知的文章，后台收到了很多消息。

大部分人说"这个有意思"，也有人直接问：那个AI访谈的框架能不能分享一下？

我觉得大家感兴趣的原因有两个。

一是自我探索这件事确实重要，但我们很少有机会获得真实的反馈。朋友不会当面说你有什么问题，同事更不会。你对自己的了解，基本靠猜。

二是我在设计这个访谈框架时，借鉴了明星访谈节目的逻辑——《十三邀》《杨澜访谈录》那种——不是问"你的价值观是什么"这种抽象问题，而是问"你当时做了什么"这样的具体行为。通过行为和决策去反推一个人的真实模式，比直接问有效得多。

当然，这个工具还在迭代。

直到前两天，我装了一个别人写的公众号排版skill。

你可能觉得排版跟访谈没什么关系，但正是这个skill让我想通了之前一直没想通的事。

先说排版的事。

我折腾公众号排版有一阵子了。自媒体人都知道，公众号编辑器是出了名的难用——粘贴HTML会丢掉大部分样式，字体、颜色、间距全乱。我之前试过用Vibe Coding写一个排版工具，结果项目做了一半就卡住了。

不是我不想做，是我发现自己跟AI说"帮我排成高级杂志风"的时候，我自己都说不清楚"高级杂志风"到底长什么样。

然后我看到了甲木老师写的gzh-design公众号排版skill。

装上去试了一下，两件事让我震惊：第一，粘贴到公众号编辑器之后，样式一点没丢。第二，我可以指定风格——石墨极简、橄榄手记、冰蓝杂志——每套都不一样，而且每个都像样。

这不是我Vibe Coding能搞出来的东西。

我很好奇。我让AI帮我逆向分析这个skill，看它到底做了什么跟我不一样的事。

分析结果让我有点明白差距在哪了。

好的skill不是"教"AI做事，是给AI一本可以逐行执行的施工手册。

你让AI写公众号HTML，它凭的是训练数据里的模糊记忆——"公众号好像要用什么leaf属性"、"颜色大概黑白色系吧"。你写"帮我排成高级杂志风"，100个模型有100种理解。

但那个skill是怎么做的？它写了三样东西。

第一样，是排版的工作流。先选主题，再读主题组件库，再装配HTML，再校验，再输出。每一步都写清楚了，AI不用猜"下一步该干什么"。

第二样，是主题风格的参考参数。叫"reference"，里面不是什么描述性文字，是精确到每个像素的HTML代码。比如冰蓝主题：#0F172A深蓝黑、#38BDF8冰蓝、48px浅灰编号、3px冰蓝竖条引用——全是硬数字。

第三样，是校验脚本。排版完成后跑一段Python脚本，自动检查有没有用禁用的标签、有没有漏掉包裹文字的span leaf。

这三样东西组成了一个系统。不是我之前那种"帮我排好看点"的对话，而是一个可执行的小系统。

**四个核心设计原则：**

1. **把LLM当"复读机"用，而不是"设计师"** — 不要指望AI自己设计出好样式，给它精确的HTML模板让它照着填空
2. **三段分离** — 决策流（SKILL.md）做推理，资产库（reference）做复制，校验脚本（validate.py）做确定性检查
3. **单一权威来源** — 颜色、字号、间距只在一个文件里定义，所有组件用同一套参数
4. **Gotchas清单** — 所有踩过的坑写成规则，下次不再犯

我回去翻了一下我写的自我访谈skill。所有内容塞在一个SKILL.md里，问题直接写在工作流里，没有校验脚本，交叉验证靠AI自己判断。就是一个提示词，不是一个系统。

于是我让AI用同样的设计哲学重新设计了它。

**改版后的 self-interview 结构：**

```
self-interview/
├── SKILL.md                    ← 344行  工作流
├── references/
│   ├── framework-full.md       ← 169行  问题库
│   └── defense-patterns.md     ← 28行   防御模式识别表
├── scripts/
│   └── validate_progress.py    ← 77行   校验器
└── data/
    └── interview-progress.json ← 60行   状态文件
```

具体改动：
- 问题全量移到 references/，SKILL.md 只引用不存储 → 单一权威来源
- 加了 validate_progress.py 校验脚本 → 确定性兜底
- 加了 Author mode 硬约束表（哪些行为允许、哪些不允许）
- 显式交叉验证规则：每3个问题自动扫描跨维度矛盾

它不是一个prompt，是一个系统。

这件事给我最大的收获不是排版问题解决了，而是我找到了一个设计AI工具的方法：

1. **找到那个reference** — 什么是一旦写准了就能锁定质量的东西？
2. **量化"是什么"，不描述"像什么"** — 写 #0F172A 深蓝黑，不写"高级杂志风"
3. **哪怕写错了也比不写强** — 先写7行reference，效果从30分跳到70分

好的skill = 把隐性知识显性化。
