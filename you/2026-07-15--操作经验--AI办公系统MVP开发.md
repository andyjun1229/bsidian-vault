# AI 智能办公系统 MVP 开发记录

**做了什么：** 基于 PRD/FDD/TDD 三份文档，完成了 AI 统一调度型智能办公系统的 MVP 开发。

**MVP 范围：** 飞书/Web 对话入口 + 出差申请 + 请假 + 报销 + 规则引擎审批

**技术选型：** FastAPI + SQLAlchemy + SQLite + DeepSeek LLM + Hermes 架构理念

**核心流程走通验证：**

| 场景 | 用户输入 | 结果 |
|------|---------|------|
| ✈️ 出差 | "我下周去上海出差两天，拜访客户"→"确认" | 自动通过（≤2000元规则） |
| 🏖️ 请假 | "明天请一天年假"→"确认" | 自动通过（≤3天规则） |
| 💰 报销 | "报销差旅费2000元"→"确认" | 待审批（>500元规则） |
| ✅ 审批 | 王经理审批通过 | 状态变为 approved |

**系统架构：**
```
用户对话（Web/IM）→ [DeepSeek LLM 意图识别] → [规则引擎匹配] 
→ [流程编排引擎] → [业务数据库] → [结果通知]
```

**关键经验：**
1. LLM 意图识别 + 规则引擎的组合比纯 LLM 判断更可靠——确定性的审批用规则引擎，不确定的意图理解用 LLM
2. 上下文管理是对话系统的核心难点——session 状态保存、确认回退都需要持久化
3. SQLite 对 MVP 够用，但 JSONB 不支持（换成 JSON），日后切 PostgreSQL 需注意
4. 规则引擎 YAML 热加载设计让审批流修改不需重启
