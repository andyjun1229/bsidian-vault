# 产品功能设计文档（FDD）
## AI 统一调度型智能办公系统

基于 PRD 的产品功能详细设计。定义每个功能模块的具体交互逻辑、触发条件、状态流转和输出物。

---

## 1. 总体交互模型

### 1.1 核心交互范式

```
用户自然语言输入 → [AI 调度中枢] → 结构化任务 → [多轮确认/补全] → 执行 → 结果反馈
```

所有功能遵循同一套交互协议：

| 步骤 | 说明 | 用户感知 |
|------|------|---------|
| 1. 意图接收 | 用户说一句话或发一个文件 | "帮我请两天假" |
| 2. 意图确认 | AI 复述理解的任务，补全缺失字段 | "好的，你明天和后天请年假，事由是什么？" |
| 3. 条件检查 | 检查预算/余额/权限/规则 | 后台执行，无感知 |
| 4. 路由决策 | 判断是否需要审批、通知谁、做什么 | "已提交给王经理审批" |
| 5. 执行 | 调 API / 写数据库 / 发通知 | 直接执行 |
| 6. 结果反馈 | 告知结果、后续动作建议 | "请假已通过，已同步到日历" |

### 1.2 异常处理通用规则

| 异常类型 | 处理策略 |
|---------|---------|
| 关键信息缺失 | AI 主动问，每次只问一个问题，直到信息完整 |
| 权限不足 | 明确告知缺少什么权限，建议找谁处理 |
| 规则冲突 | 展示冲突原因，给出推荐方案让用户选 |
| 系统错误 | "系统暂时无法处理，已记录工单，稍后重试" |
| 用户意图模糊 | 提供 2-3 个候选理解让用户确认 |

## 2. 功能模块详细设计

### 2.1 OA 办公模块

#### 功能 OA-01：出差申请

| 字段 | 说明 |
|------|------|
| 触发条件 | 用户表达出差/出差申请/去某地出差意图 |
| 必需字段 | 目的地、开始时间、结束时间、事由 |
| 可选字段 | 预算预估、交通方式、住宿要求、同行人 |
| 补全策略 | AI 依次询问缺失字段，每次一问 |
| 规则检查 | 部门预算、差旅标准（住宿上限/交通等级）、出差频次限制 |
| 流程路由 | 金额≤2000 → 直属上级审批；>2000 → 上级+部门经理 |
| 执行动作 | 生成出差单→提交审批→预占预算→日历标记外出→可选预订差旅 |
| 输出物 | 出差申请单（含审批状态）、差旅预订确认（如有） |
| 后续通知 | 审批通过/驳回→通知申请人；超时未审→催办审批人 |

**对话示例：**
```
用户: 我下周一去上海出差两天
AI: 好的，下周一（7月21日）到下周二（7月22日）去上海出差。
请问出差事由和预算预估是多少？
用户: 拜访客户，预算大概3000
AI: 已记录。出差申请已提交给张经理审批，同时预占部门差旅预算3000元。
出差期间的日历已标记为外出。需要我帮你查看差旅标准内的酒店吗？
```

#### 功能 OA-02：请假申请

| 字段 | 说明 |
|------|------|
| 触发条件 | 请假/休假/休息一天/请年假 |
| 必需字段 | 请假类型（年假/事假/病假/调休）、开始时间、结束时间 |
| 可选字段 | 事由、工作交接人 |
| 补全策略 | 先问类型，再问时间，再问事由 |
| 规则检查 | 假期余额是否充足、连续请假天数限制、部门在岗人数 |
| 流程路由 | ≤3天 → 直属上级；>3天 → 上级+HR |
| 执行动作 | 生成请假单→提交审批→日历标记→通知工作交接人（如有） |
| 通知模板 | "XX请假已审批通过/驳回" |

#### 功能 OA-03：用车申请

| 字段 | 说明 |
|------|------|
| 触发条件 | 申请用车/派车/去某地需要车 |
| 必需字段 | 时间、出发地、目的地、事由 |
| 流程路由 | 公事→行政派车；私事→不提供（告知替代方案） |
| 执行动作 | 查可用车辆→派车→通知司机→通知申请人 |

#### 功能 OA-04：办公用品申领

| 字段 | 说明 |
|------|------|
| 触发条件 | 领用/申领/缺少办公用品 |
| 必需字段 | 物品名称、数量 |
| 规则检查 | 库存是否足够、个人月度领用限额 |
| 流程路由 | 标准品（笔/纸/墨盒）→自动通过；非标品→行政审批 |
| 执行动作 | 扣库存→通知行政配送到工位→记录领用台账 |

#### 功能 OA-05：用印申请

| 字段 | 说明 |
|------|------|
| 触发条件 | 盖章/用印/需要公章 |
| 必需字段 | 文件名称、用途、用印类型（公章/合同章/财务章） |
| 流程路由 | 公章→部门负责人+行政经理+法务（如有）；合同章→部门负责人+法务 |
| 执行动作 | 验证文件→提交审批→通知用印人到行政办公室 |
| 安全约束 | 必须上传或指明文件位置，AI 做基本校验 |

#### 功能 OA-06：通知公告发布

| 字段 | 说明 |
|------|------|
| 触发条件 | 发通知/发公告/全员通知 |
| 必需字段 | 标题、内容、发布范围（全员/部门/指定人） |
| 流程路由 | 全员范围→部门负责人+行政审核；部门范围→仅部门负责人审核 |
| 执行动作 | 生成通知→提交审核→审核通过后发布→IM推送 |

### 2.2 财务管理模块

#### 功能 FIN-01：费用报销

| 字段 | 说明 |
|------|------|
| 触发条件 | 报销/报销费用 |
| 必需字段 | 费用类型（差旅/招待/办公/其他）、金额、发生时间 |
| 自动关联 | 如有关联的出差申请/采购单，AI 自动识别并关联 |
| 输入方式 | 手动描述 或 上传发票图片（OCR 提取） |
| 规则检查 | 是否在预算内、发票是否合规、是否超标 |
| 流程路由 | ≤500 → 自动通过；500-5000 → 上级审批；>5000 → 上级+财务 |
| 执行动作 | 关联出差申请→提取支付记录→填写报销单→提交→财务打款 |
| 通知 | 报销到账通知申请人 |

#### 功能 FIN-02：付款申请

| 字段 | 说明 |
|------|------|
| 触发条件 | 要付款/支付/付给供应商 |
| 必需字段 | 收款方、金额、合同号/采购单号（如有）、付款事由 |
| 规则检查 | 合同付款条件是否满足、预算是否充足 |
| 流程路由 | ≤10000 → 部门经理；>10000 → 部门经理+财务经理+CFO（如有） |
| 执行动作 | 验证合同→提交审批→通知出纳执行→标记付款完成 |

#### 功能 FIN-03：预算查询与分析

| 字段 | 说明 |
|------|------|
| 触发条件 | 查预算/还剩多少钱/预算分析 |
| 必需字段 | 预算范围（部门/项目/公司）、时间周期（本月/本季/本年） |
| 输出格式 | 自然语言摘要 + 结构化数据（可选图表） |
| 权限控制 | 普通员工只看自己部门；部门经理看本部门；财务看全局 |

**输出示例：**
```
AI: 你所在的研发部本月预算50万，已使用32万（64%），剩余18万。
主要支出在：服务器采购15万、外包服务10万、办公用品7万。
其中服务器采购预算剩余5万，如有新需求建议下月再提。
```

#### 功能 FIN-04：发票管理

| 字段 | 说明 |
|------|------|
| 触发条件 | 登记发票/开发票/上传发票 |
| 输入方式 | 上传图片（支持拍照） |
| 执行动作 | OCR 识别→税务验真→登记入账→返回登记编号 |
| 特殊情况 | 发票信息模糊→AI 标注不确定字段让用户确认 |

#### 功能 FIN-05：费用分析

| 字段 | 说明 |
|------|------|
| 触发条件 | 费用分析/花钱分析/看看哪里花钱多 |
| 输出格式 | 按部门/类型/时间维度的分析摘要 |
| 可选深化 | "帮我跟去年同期做个对比" |

## 3. 通用功能设计

### 3.1 身份与权限系统

| 设计项 | 说明 |
|--------|------|
| 身份来源 | 对接 IM 平台（飞书/企微/钉钉）组织结构 |
| 角色体系 | 系统预置：员工、部门经理、财务、HR、管理员；支持自定义 |
| 权限粒度 | 操作级权限（申请/审批/查看/导出）+ 数据级权限（本人/部门/全公司） |
| 权限校验时机 | 每条指令执行前 |
| 权限变更 | 管理员通过自然语言赋权："给财务部的小张开通查看全公司报销的权限" |

### 3.2 审批流设计

审批流不再需要预先在界面里画图配置，而是通过规则引擎描述：

```yaml
rules:
  - name: "差旅报销审批链"
    conditions:
      - field: amount
        operator: lte
        value: 500
    action: auto_approve

  - name: "差旅报销审批链"
    conditions:
      - field: amount
        operator: gt
        value: 500
      - field: amount
        operator: lte
        value: 5000
    action: 
      - type: approval
        approver: direct_manager
      - type: notify
        to: finance

  - name: "差旅报销审批链"
    conditions:
      - field: amount
        operator: gt
        value: 5000
    action:
      - type: approval
        approver: direct_manager
      - type: approval
        approver: finance_manager
```

### 3.3 主动服务设计（Cron/定时触发）

| 服务 | 触发频率 | 动作 |
|------|---------|------|
| 每日简报 | 每天 9:00 | 推送待办审批 + 今日日程 + 预算预警 + 合同到期提醒 |
| 审批催办 | 每 24h（超时后） | 催办超时未审的审批人 |
| 预算预警 | 预算使用达 80%/90%/100% | 通知部门负责人 |
| 合同到期提醒 | 到期前 30/15/7 天 | 通知合同负责人 |
| 员工生日祝福 | 当天 10:00 | 自动发送祝福 + HR 后台记录 |
| 考勤异常提醒 | 每天 10:00 | 通知昨日缺卡人员 |

### 3.4 对话状态管理

```
对话状态结构：
{
  "session_id": "xxx",
  "user_id": "xxx",
  "current_intent": "leave_apply",
  "collected_fields": {
    "type": "年假",
    "start_date": "2026-07-21",
    "end_date": "2026-07-22",
    "reason": null  ← 待补全
  },

```
