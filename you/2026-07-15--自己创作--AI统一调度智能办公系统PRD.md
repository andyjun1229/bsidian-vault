# AI 统一调度型智能办公系统 PRD

## 1. 产品概述

### 1.1 一句话定义

一个以 AI Agent 为统一调度中枢的智能办公系统，用户通过自然语言输入即可完成 OA 审批、财务报销、人事管理、采购合同、项目协作等全部业务流程，无需手动选择菜单、点击按钮或走传统审批流。

### 1.2 核心主张

> 传统办公系统让用户适应机器（菜单→表单→按钮→流程）
> 这个系统让机器适应人（说话→AI理解→AI执行→结果反馈）

用户只需要说"我要申请出差""帮我报销一笔差旅费""给我安排下个月的招聘面试""新员工入职了帮我办好手续"——剩下的全部由 AI 自主调度完成。

### 1.3 解决的问题

| 传统系统痛点 | AI 调度方案 |
|-------------|------------|
| 功能分散在几十个菜单里，新员工找不到入口 | 单一对话入口，自然语言直达 |
| 每个审批流要预设节点，改流程要 IT 介入 | Agent 动态判断流程，按规则自动路由 |
| 跨部门协作要手动抄送/催办 | Agent 自动识别干系人并推送 |
| 数据查询要进不同模块（财务/人力/项目） | Agent 统一调度数据源，返回结论 |
| 表单填写重复繁琐 | AI 从上下文提取信息自动填充 |
| 催办/提醒靠人为跟进 | Agent 按超时规则自动推送 |

## 2. 目标用户

- **中小企业（20-500人）** — 没有专职 IT 部门，需要一个能快速上手、不用培训的系统
- **部门管理者** — 日常审批多、需要快速决策，不想在系统操作上花时间
- **一线员工** — 不想记住系统怎么用，把事情交代给 AI 就行
- **企业主/CEO** — 通过自然语言直接获取全局信息："我这个月人力成本多少""项目A的进度什么情况"

### 3.1 架构分层说明

**第一层：用户入口**
- 支持飞书、企微、钉钉、微信等即时通讯工具作为终端
- 纯对话界面，无传统 UI 菜单
- 语音输入可选

**第二层：AI Agent 调度中枢（核心）**
- **意图识别引擎**：判断用户输入的意图（"我要出差"→出差申请流程，"报销"→报销流程，"小王怎么样"→查询员工绩效）
- **上下文管理**：多轮对话中保持状态（例如先问"出差去哪"→"上海"→"什么时间"→"下周一"→"预计花费"→"3000"→AI 确认后提交）
- **权限校验**：判断当前用户身份和权限范围（普通员工只能提交自己相关的，经理可以审批下属的，财务可以查看全局报销数据）
- **流程编排引擎**：将识别出的任务拆解为可执行步骤，跨模块调度

**第三层：业务模块**
- 每个模块独立，可插拔（企业按需开通）
- 模块之间通过 Agent 调度中枢通信，非直接耦合
- 每个模块有独立的规则配置（审批链、预算控制、合规检查等）

### 3.2 Agent 编排引擎的工作流

以"员工出差"为例，AI 的完整处理链路：

```
用户说： "我下周一要去上海出差三天，帮我申请一下"

Step 1 — 意图识别
  ↓
  "出差申请" → 匹配 OA 模块

Step 2 — 信息收集（主动询问补全）
  ↓
  AI: "出差地点是上海，时间下周一到周三，请问出差事由和预算预估是多少？"
  用户: "拜访客户，预算大概 3000"

Step 3 — 规则检查
  ↓
  - 验证员工身份/部门
  - 检查部门预算是否充足
  - 检查是否有差旅标准（例如单日住宿上限）

Step 4 — 流程路由
  ↓
  生成出差申请单 → 自动提交给直属上级审批
  同步通知财务部预算预占
  推送到日程模块（出差期间的日历自动标记为外出）

Step 5 — 结果通知
  ↓
  上级审批通过后 → AI 通知用户：
  "出差申请已通过。已为你预订了差旅标准内的酒店（可选不同档次）和交通方式。需要我帮你一起订吗？"
```

所有交互都在对话中完成，用户不需要进入任何系统界面。

## 5. 核心差异化设计

### 5.1 全程自然语言

这是最核心的差异点。传统 OA 的设计逻辑是"用户学习系统"，这套系统是"系统理解用户"。

**关键设计原则：**
- AI 永远主动提问补全信息，而不是让用户去填表单
- 每次对话都能识别身份和上下文，不需要重复提供已知道的信息
- 开放式输入和标准化输出之间的映射由 Agent 完成

### 5.2 动态流程编排

传统系统是**静态流程**（预设好的审批链，改起来要 IT 介入）。
这套系统是**动态流程**——Agent 根据任务内容、金额、部门、用户角色实时决定流程路径。

**示例：**
- 报销 500 元以下 → 自动通过，无需审批
- 报销 500-5000 元 → 直属上级审批
- 报销 5000 元以上 → 上级 + 财务经理审批
- 差旅费报销 → 自动关联出差申请单校验

规则在配置文件中定义，修改不需要重启系统。

### 5.3 主动式服务

传统系统是**被动响应**（用户点→系统做）。
这套系统是**主动服务**：

- 超时未审批 → AI 自动催办审批人
- 预算即将超支 → 提前通知部门负责人
- 合同即将到期 → AI 主动提醒续签
- 员工生日 → AI 自动发祝福和提醒 HR
- 每日简报 → 早上推送待办事项、未审批流程、重要提醒

### 5.4 权限与安全

- 对话层身份认证（对接 IM 平台的身份体系或自建 OAuth）
- 每条指令执行前校验：当前用户的角色、部门、权限范围
- 敏感操作（付款、修改合同、批量删除）需要二次确认
- 所有对话记录和执行日志可追溯审计
- 可选：敏感信息脱敏（普通查询只看脱敏数据，财务权限看完整数据）

## 6. 技术方案建议

### 6.1 推荐技术栈

| 层 | 技术选型 | 说明 |
|----|---------|------|
| AI Agent 框架 | Hermes Agent / LangChain / AutoGPT | 作为调度中枢和编排引擎 |
| 大模型 | GPT-5.6 / DeepSeek / Claude | 意图识别、信息提取、任务规划 |
| 业务数据层 | PostgreSQL + Redis | 结构化业务数据和缓存 |
| 文件/文档存储 | MinIO / OSS | 发票/合同/附件 |
| 消息推送 | 飞书/企微/钉钉 Bot API | 通知和交互 |
| 会话管理 | WebSocket + 长连接 | 保持对话状态 |
| 部署 | Docker + K8s 或 单机 Docker Compose | 中小企业可简化部署 |

### 6.2 AI 调度架构核心实现思路

```
用户输入 → [意图识别 Agent] → 结构化任务 JSON
                                ↓
               [流程编排 Agent] → 拆解子步骤
                                ↓
               [模块执行 Agent] → 调业务 API / 写数据库
                                ↓
               [结果聚合 Agent] → 自然语言回复 + 通知
```

### 6.3 数据模型核心实体

```
用户（角色/部门/权限）
流程实例（状态/当前节点/历史记录）
业务单据（报销单/请假单/合同/项目等）
规则配置（审批链/预算控制/条件分支）
消息记录（对话历史/通知记录）
```

## 7. 分阶段实施规划

### Phase 1 — MVP（4-6 周）

- 飞书/企微单入口对接
- OA 核心场景：出差申请、请假、报销
- Agent 调度中枢基础能力（意图识别 + 信息补全 + 流程路由）
- 3 条审批规则（按金额分级）
- 权限校验基础版（角色判断）

### Phase 2 — 扩展（6-8 周）

- 财务管理：付款申请、预算查询、发票登记
- 人力资源管理：入职/离职流程、绩效查询
- 项目管理：任务分配、进度查询、周报生成
- 审批规则可视化配置界面
- 主动提醒（催办、到期提醒）

### Phase 3 — 完善（持续迭代）

- 采购/合同管理模块
- 多模态输入（图片发票识别、语音输入）
- 自定义流程配置（管理者可自己编写新流程规则）
- 数据分析与看板（自然语言查询 BI 数据）
- Skill 体系（让管理者可以像装 App 一样装新模块）

## 8. 竞品分析

| 产品 | 核心方式 | AI 程度 | 差距 |
|------|---------|---------|------|
| 钉钉/企微 | 传统菜单+审批流 | AI 辅助（文字转审批） | 本质还是表单+按钮 |
| 飞书 | 集成 AI 助手 | 可以查日程/摘要 | 不能跨模块调度 |
| 用友/金蝶 | 流程引擎+表单配置 | 低 | 传统 ERP 思路 |
| 轻流/明道云 | 零代码流程搭建 | 中 | 仍需配置 |
| 本产品 | 纯对话 AI 调度 | 高 | 用户无需做任何配置操作 |

**核心差异化：** 其他产品是在"有 UI 的系统上加 AI 助手"，本产品是"AI 即系统"——用户根本不需要知道系统长什么样。

## 9. 风险与应对

| 风险 | 可能性 | 应对 |
|------|--------|------|
| AI 意图识别不准导致错误操作 | 中 | 关键操作前做确认环节；保留人工撤销能力；操作留痕 |
| 用户不习惯纯对话操作 | 中 | 初期保留简单的 UI 视图（查看功能）；渐进式过渡 |
| 审批规则复杂时 AI 判断出错 | 中 | 规则从简单开始，逐步扩充；规则验证脚本兜底 |
| 多轮对话上下文丢失 | 低 | 持久化会话状态；关键字段结构化存储 |
| 权限误判信息泄露 | 低 | 二次确认；最小权限原则；审计日志 |

## 10. 验收标准

1. 新增用户能在 5 分钟内完成第一个操作（如"请两天假"），无需任何培训
2. 典型场景（出差/报销/请假）的全流程走通率 ≥ 95%
3. AI 主动补全正确率（无需用户纠正）≥ 90%
4. 审批规则执行正确率 100%（这是底线，涉及钱和权）
5. 单次任务平均交互轮次 ≤ 5 轮（用户说一次→AI 问 2-3 次→确认→完成）
6. 权限零泄露：未授权用户无法执行或查看超权限操作
