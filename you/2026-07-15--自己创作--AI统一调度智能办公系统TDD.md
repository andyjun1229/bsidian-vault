## 2. 技术栈详细选型

### 2.1 后端核心

| 组件 | 选型 | 版本 | 选型理由 |
|------|------|------|---------|
| 编程语言 | Python | 3.12 | AI Agent 生态最好，LangChain/Hermes 原生支持 |
| Web 框架 | FastAPI | 最新 | 异步原生，天然支持 WebSocket，性能好 |
| Agent 框架 | Hermes Agent | - | 你已经在用，Skill 体系、cron、memory 全覆盖 |
| 流程编排 | 自研编排引擎 | - | 基于规则引擎 + LLM 调用，轻量灵活 |
| ORM | SQLAlchemy 2.0 + Alembic | - | 成熟稳定，迁移管理方便 |
| 消息队列 | Redis Pub/Sub + Celery | - | 异步任务（通知/催办/定时） |

### 2.2 大模型相关

| 组件 | 选型 | 说明 |
|------|------|------|
| 主模型 | DeepSeek / GPT-5.6 | 意图识别+编排+生成，根据成本和场景切换 |
| 意图分类 | 小模型（如 BERT）或 LLM Few-shot | MVP 阶段直接用 LLM，后期可蒸馏小模型 |
| Embedding | text-embedding-3-small | 用于语义搜索和 FAQ 匹配 |
| OCR | PaddleOCR / 飞书文档 OCR | 发票识别 |
| TTS（可选） | Edge TTS / 火山引擎 | 语音播报结果 |

### 2.3 基础设施

| 组件 | 选型 | 说明 |
|------|------|------|
| 数据库 | PostgreSQL 15+ | 业务数据，JSONB 支持灵活 schema |
| 缓存 | Redis 7+ | 会话状态、规则缓存、消息队列 |
| 文件存储 | MinIO 或 OSS | 发票/合同/附件 |
| 部署 | Docker Compose | MVP 单机部署；后期可升 K8s |
| CI/CD | GitHub Actions | 自动测试+部署 |

```sql
    end_date DATE NOT NULL,

    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    description TEXT,

    related_trip_id UUID REFERENCES business_trips(id),

-- ========== 规则配置 ==========
CREATE TABLE workflow_rules (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    created_at TIMESTAMP DEFAULT now()

-- ========== 对话记录 ==========
CREATE TABLE conversation_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

CREATE TABLE scheduled_tasks (
```

## 5. Agent 调度中枢核心实现

### 5.1 意图识别管线

```
输入: "我下周要去上海出差两天"

1. 意图分类器
   → 输出: {"intent": "business_trip_apply", "confidence": 0.96}
   
2. 实体提取 (NER)
   → 输出: {"destination": "上海", "start_date": "2026-07-21", 
            "duration": "2天", "end_date": "2026-07-22"}
   
3. 字段校验
   → 检查必需字段: destination✅, start_date✅, end_date✅, purpose❌, budget❌
   → 缺失: purpose, budget → 主动提问

4. 结构化任务
   → {
       "type": "business_trip_apply",
       "fields": {...},
       "missing_fields": ["purpose", "budget"],
       "status": "collecting"
     }
```

### 5.2 流程编排引擎伪代码

```python
class WorkflowEngine:
    def execute(self, intent: StructuredIntent, user: User):
        # 1. 补全信息
        while intent.missing_fields:
            question = self.generate_question(intent.missing_fields[0])
            reply = self.ask_user(question)
            intent.fields[reply.field] = reply.value
        
        # 2. 确认
        if not self.user_confirms(intent):
            return self.cancel()
        
        # 3. 加载规则
        rules = RuleLoader.load(intent.type)
        
        # 4. 逐条匹配规则
        matched_actions = []
        for rule in sorted(rules, key=lambda r: r.priority):
            if self.match_conditions(rule.conditions, intent.fields, user):
                matched_actions = rule.actions
                break
        
        # 5. 执行动作
        result = self.execute_actions(matched_actions, intent.fields, user)
        
        # 6. 通知
        self.notify(result)
        
        return result
    
    def match_conditions(self, conditions, fields, user):
        # 示例条件: amount > 500 and amount <= 5000
        # 支持: 字段比较 / 角色判断 / 部门判断 / 逻辑组合(and/or/not)
        ...
```

### 5.3 Rule Engine（规则引擎）

规则引擎是核心——它替代了传统 OA 的审批流配置界面。规则用 YAML 编写，热加载，改后即时生效。

```yaml
# config/rules/business_trip.yaml
rules:
  - name: "差旅自动通过"
    priority: 10
    conditions:
      all:
        - field: budget_estimate
          operator: lte
          value: 2000
        - field: user.role
          operator: in
          value: [manager, director]
    actions:
      - type: auto_approve
      - type: notify
        to: [initiator]
      - type: mark_calendar
      - type: pre_occupy_budget
  
  - name: "差旅上级审批"
    priority: 20
    conditions:
      all:
        - field: budget_estimate
          operator: gt
          value: 2000
        - field: budget_estimate
          operator: lte
          value: 5000
    actions:
      - type: create_workflow
        steps:
          - approver: direct_manager
      - type: notify
        to: [initiator, direct_manager]
      - type: pre_occupy_budget
  
  - name: "差旅多级审批"
    priority: 30
    conditions:
      any:
        - field: budget_estimate
          operator: gt
          value: 5000
    actions:
      - type: create_workflow
        steps:
          - approver: direct_manager
          - approver: finance_manager
      - type: notify
        to: [initiator, direct_manager, finance_manager]
      - type: pre_occupy_budget
```

## 6. 模块间通信

### 6.1 Agent 调度层 ↔ 业务服务层

```
方式: HTTP API 调用（同进程内或跨服务）
协议: RESTful JSON
认证: 内部 Token 或 mTLS

Agent 不直接写数据库，通过业务服务 API 操作。
业务服务不调用 LLM，通过 Agent 调度层获取意图。
```

### 6.2 消息通知

```
方式: IM Bot API（飞书/企微/钉钉）
内容: 审批通知 / 催办 / 结果反馈 / 每日简报 / 预警
格式: 富文本（支持按钮交互：审批/驳回/查看详情）
```

### 6.3 定时任务

```
方式: Cron（Hermes cron 或 Celery Beat）
任务: 每日简报 / 审批催办 / 预算预警 / 合同到期提醒
状态: Redis 记录上次执行时间，避免重复执行
```

## 9. 关键设计决策记录

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 审批流配置方式 | 可视化拖拽 / 规则引擎YAML / 全LLM判断 | 规则引擎YAML | 可视化太重，全LLM不可控；YAML兼顾灵活性和确定性 |
| 业务流程数据存储 | 关系型 / 文档型 / 图 | 关系型(PostgreSQL) | 事务一致性和审批流状态管理要求高 |
| 意图识别 | 小模型分类器 / LLM Few-shot / 两者混合 | MVP用LLM，后期混合 | 小模型精度不够，LLM省去标注成本，后期量大了再蒸馏 |
| Agent框架 | Hermes / LangChain / 自研 | Hermes Agent | 你已用 Hermes，Skill体系+cron+memory现成可用 |
| 对话界面 | 纯对话 / 对话+混合UI | MVP纯对话，Phase2加简单UI | PRD核心主张就是纯对话，初期不做UI干扰验证 |

## 10. 开发与测试策略

### 10.1 开发顺序（按 MVP 范围）

```
Week 1-2: 基础设施
  - 数据库建表 + Alembic 迁移
  - FastAPI 脚手架 + WebSocket
  - IM Bot 对接（飞书/企微）
  - 身份认证与权限校验

Week 3-4: 核心引擎
```

### 10.2 测试策略

| 测试类型 | 范围 | 方法 |
