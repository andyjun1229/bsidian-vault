## 逐层拆解

### L1：公众号排版的基本认知
**定义：** 知道公众号编辑器怎么用、有哪些排版限制、样式粘贴后会丢失。

| 检查项 | 会/不会 | 备注 |
|--------|---------|------|
| 知道公众号编辑器只接受纯 `<section>` 正文片段，不能有 `<html>/<head>/<body>` | | |
| 知道必须用内联 style，不能用 CSS class | | |
| 知道所有文字节点要包 `<span leaf="">` 否则样式丢失 | | |
| 知道禁止用 `<style>/<script>/<div>/position:fixed/absolute/float/grid` | | |
| 知道在电脑上预览和手机预览的区别 | | |

### L2：理解公众号 HTML 的约束条件
**定义：** 知道「什么能做什么不能做」背后为什么这么设计的，能判断一段 HTML 能不能直接用。

| 检查项 | 会/不会 | 备注 |
|--------|---------|------|
| 知道为什么微信公众号不能用 `<style>` 标签 | | |
| 知道 `span leaf=""` 是做什么的（WeChat 编辑器渲染机制） | | |
| 知道为什么 `white-space:pre` 在代码块里不能用（缩进出问题） | | |
| 知道 `max-width:100%` vs `width:100%` 对图片的影响 | | |
| 知道半角/全角标点在公众号编辑器中呈现的差异 | | |

### L3：能手动拼出一套排版 HTML
**定义：** 能基于组件库，把一篇 Markdown 文章转换成交付级排版 HTML。

| 检查项 | 会/不会 | 备注 |
|--------|---------|------|
| 能根据 theme-index 选主题 | | |
| 能解析 Markdown 结构（标题/段落/引用/列表/代码块） | | |
| 能按主题库的「文章类型→组件组合配方」选组件 | | |
| 能执行章节自动编号（`01/02/...∞`） | | |
| 能生成英文标签（TUTORIAL / SUMMARY / THOUGHTS 等） | | |
| 能每段识别 1-3 个关键词加下划线（核心特色标记） | | |
| 能从 `# 标题` 提取前 3 个生成本文看点 | | |
| 能拼装封面刊头（深蓝底+标签条+日期+标题+摘要） | | |
| 能拼装结语章节（编号用 ∞） | | |
| 能拼装作者签名区 | | |
| 能拼装结尾行动区 | | |
| 能用通用增量库处理代码块、图片、小标签 | | |
| 能用校验脚本检查合规（validate_gzh_html.py） | | |
| 能用预览包装脚本生成带复制按钮的 HTML | | |
| 能处理一次排版中的常见故障：半角引号、漏 span leaf、章节编号错乱 | | |

### L4：能抽象出「主题组件库」的数据结构
**定义：** 知道一个完整的主题组件库应该包含哪 5 个部分，能设计出一个新主题。

| 检查项 | 会/不会 | 备注 |
|--------|---------|------|
| 知道组件库必须包含设计变量速查表 | | |
| 知道组件库必须包含各组件完整 HTML（内联样式+span leaf） | | |
| 知道组件库必须包含完整文章模板骨架 | | |
| 知道组件库必须包含「文章类型→组件组合配方」表 | | |
| 知道组件库必须包含 Markdown→组件映射规则表 | | |
| 能独立设计一套新的封面刊头组件 | | |
| 能独立设计一套新的章节标题组件（大号编号+英文标签+标题） | | |
| 能独立设计一套新的正文关键词标记样式（下划线/高亮/加粗变体） | | |
| 能独立设计一套金句引用/提示框/代码块组件 | | |
| 能独立设计一套作者签名/结尾行动区 | | |
| 能在 theme-index.md 中登记新主题 | | |
| 能跑 component_lint.py 到 0 ERROR | | |

### L5：能把组件库变成「可被 Agent 调用的 Skill」
**定义：** 知道怎么把上面所有的知识封装成一个 Hermes Skill，让 AI 能自行完成排版。

| 检查项 | 会/不会 | 备注 |
|--------|---------|------|
| 知道 Skill 的三层架构（SKILL.md + references/ + scripts/） | | |
| 知道 SKILL.md 中应该写什么（流程/决策规则/边界/忌讳） | | |
| 知道什么时候用 references/ 存储核心资产（组件库等） | | |
| 知道什么时候用 scripts/ 做确定性校验 | | |
| 知道怎么设计「校验脚本」来兜底 AI 的错误 | | |
| 知道怎么设计「主题选择决策规则」让 AI 不瞎选 | | |
| 知道怎么把 Gotchas（踩过的坑）作为 Skill 的一部分 | | |
| 知道怎么测试自己的 Skill 是否可靠（回归用例） | | |

### L6：能设计出别人也能贡献主题的「排版系统」
**定义：** 理解什么是「系统设计」——不只是做一个工具，而是做一个框架让别人也能在上面建东西。

| 检查项 | 会/不会 | 备注 |
|--------|---------|------|
| 知道三分离架构（工作流/资产库/校验器）的设计原理 | | |
| 知道为什么用「主题->组件库->映射规则」而不是「每个主题一个 prompt」 | | |
| 知道「单一权威来源」的设计原则（theme-index 是所有信息的 SSOT） | | |
| 知道 API 优先的设计思路（组件库是数据，SKILL.md 是程序） | | |
| 知道怎么设计「自定义主题生成器」（theme-generator.md）让别人不用写代码也能加主题 | | |
| 知道怎么通过 archive/ 做版本管理而不是直接删除旧代码 | | |
| 知道怎么设计「质量闭环」（排版→校验→修复→再校验） | | |
