# K3 开源震惊世界，但我更在意那个不透明的账单

> 开源是好事，K3 也确实强。但作为一个付了费的普通用户，我想聊一件比参数更重要的事。

最近 AI 圈最热的话题，卡兹克那篇《黄仁勋、Kimi K3，与一场即将到来的开源战争》已经讲得很清楚了。

7 月 17 日 Kimi K3 发布，2.8 万亿参数，百万 Token 上下文。7 月 22 日白宫指控"蒸馏 Claude"。7 月 24 日黄仁勋人生第一条 X，77 家科技公司联名上书反对封禁开源。7 月 27 日 K3 正式开源——不只是权重，技术报告、MoonEP 通信库、FlashKDA 算子、AgentENV 沙箱，全拿了出来。

我跟卡兹克一样，认为这是一件了不起的事。一个中国团队，在算力远没有那么宽裕的情况下，做出了全球首个 3T 级开源模型，还把训练底层设施一并公开。

「这是真心话。K3 确实强。」

但今天我想聊的不是宏大叙事。我想从另一个角度——一个真实付费用户的视角——说说我的体验。

## 我用 K3 做了个 APP，体验是好的

我最近在做一个叫「自我访谈」的 APP。Next.js 全栈，32 个源文件，七千多行代码。

全程用 Kimi Code 开发，Moderato 套餐，月付 ¥99。

先说结论：K3 的能力没让我失望。复杂的状态机逻辑、多文件联动修改、服务器部署排错——K3 都能处理。中间有一次题型混编大改，同时动 7 个文件，K3 也扛住了。

K3 在 Agent 编程场景下的能力，是经过我个人实战验证的。这不是客套话。

但问题出在账单上。

## 项目做到三分之二，额度没了

不是月末。是一周的额度直接归零。

Kimi Moderato 的周额度，根据社区实测反推，大约 1 亿 Token。我的 APP 还没写完，这一亿就用完了。

为了验证，我把同样的开发量，拿到 DeepSeek 的 API 后台去对标。

「同一项目，Kimi 一周烧了 1 亿 Token，DeepSeek API 只花了 ¥62。」

我的 DeepSeek 账户近 30 天的数据是这样的：V4 Pro 调用 641 次，消耗 1.04 亿 Token；V4 Flash 调用 8686 次，消耗 11.69 亿 Token。合计消费 ¥62.44。

需要说明：这个对比不是完全对等的。DeepSeek 的数据包含了 V4 Flash 的大量轻量调用，不一定都是重度 Agent 任务。同样的任务在 K3 上能不能跑通、跑得怎么样——这些没有 AB 测试，不能下结论说"Kimi 更贵"。

但有一点是确定的。

## Kimi 不告诉我，我的钱花在哪了

Kimi Moderato 额度耗尽之后，我做的第一件事是去找我的 Token 消耗明细。

没找到。

订阅页面只有一个「我的额度」标签。点进去——没有 Token 数字，没有每条对话的消耗，没有峰值时段分析。只有一列权益说明。

而 DeepSeek 的后台：每一次 API 调用，输入多少 Token、输出多少 Token、缓存命中多少、按模型分列的详细图表、日级消费趋势——清清楚楚。

如果 Kimi 告诉我这一周消耗了多少 Token、哪些任务是消耗大头——那我花 ¥99 花得明明白白。

现在的情况是：K3 的能力是透明的，K3 的收费是不透明的。

## 能力归能力，账单归账单

我写这篇文章，不是在说 Kimi 不好。

恰恰相反。K3 很强。我在上面完成了一个真实 APP 的开发，这是事实。DeepSeek 能不能完成同样的任务——我不知道，我没测过。某些复杂场景下 K3 做得更好的可能性完全存在。

我不是在说"别用 Kimi"。我是在说——作为一个好产品，你应该让用户知道钱花在哪了。

这不是什么过分的要求。这在任何消费场景里都是基本操作。移动运营商给你话费明细。云服务商给你资源用量。外卖平台给你订单记录。AI 订阅服务凭什么例外？

能力是产品力。透明度也是产品力。

## 写在最后

K3 开源是好事。K3 的能力也值得认可。

但作为一个付了费的普通用户，我想说的不是 2.8 万亿参数，不是 MoonEP，不是 AgentENV。我想说的是：你连一个 Token 消耗明细都不给我，我怎么知道我这一周的额度是被什么吃掉的？

能力是产品力。透明度也是产品力。

DeepSeek 在这一点上做得更好。Kimi 如果能把这点补上，我会是它的忠实用户——因为 K3 的能力我真的认可。
