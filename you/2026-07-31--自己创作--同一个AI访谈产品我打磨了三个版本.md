# 同一个AI访谈产品，我打磨了三个版本

两个月前，我用 OpenClaw 智能体跟自己进行了一场深度对话。63 道题，7 个维度——决策逻辑、人际模式、学习成长、价值观、防御机制、能力图谱、家庭与身份。

那个智能体不是聊天机器人。它有一个 Agent Loop 状态机——WARM→OPEN→ASK→LISTEN→DECIDE→PROBE/SWITCH/CLOSE→REFLECT。每收到一句回答，它自己判断：追问还是换话题还是收尾。对话结束后自动更新画像、追加时间线、提取行为模式、跑四家哲学合成。

我把整个过程写成了文章「我用AI做了一次深度自我访谈」。后台收到不少反馈——有人说"做完感觉被看穿了"，有人说"能不能让我妈也用一下"。

前一个反馈让我觉得方向对了。后一个反馈让我意识到：门槛太高了。

---

## V0：跟 AI 智能体对话——验证这件事值不值得做

这一版没有 Web，没有数据库，连界面都没有。就是 OpenClaw 上跑的一个 skill。

九个状态。九个。WARM 暖场，OPEN 开场白，ASK 提问，LISTEN 收回答，DECIDE 判断下一步，PROBE 追问，SWITCH 切换维度，CLOSE 收尾，REFLECT 后台更新画像。

Agent 的追问逻辑是代码写的规则 + LLM 判断两层把关。用户说"还行"——先触发关键词检测，再交给 LLM 判断是真敷衍还是真简单。两层都通过才追问。追问最多两次——追问太多就不是访谈，是审讯。

这个版本只做了一件事：验证核心假设。

DeepTalk 的核心假设不是"AI 能做访谈"——那个太容易验证了。真正的核心假设是：**63 道追问式的问题，能不能让一个人产生"被看穿了"的感觉？**

我拿自己当小白鼠跑了好几轮。我老婆试了。几个朋友试了。反馈足够正面——方向定了。

**学到的事：先验证核心假设，再建产品。有一件事，如果它不成立，整个产品就不值得做——这件事是什么？在写第一行代码之前，怎么验证它？**

## V1：从 Agent 对话到 CLI 工具——把追问机制封装成一个产品

V0 验证了"追问答题"这个形式有价值。但它寄生在 OpenClaw 里，别人没法用。

于是我把那套 Agent Loop 拆了出来，做成一个独立的 CLI 工具。叫 deeptalk。

Python 项目，pip install -e .，deeptalk 命令启动。Terminal 里打字聊天。Agent 追问机制完整保留——敷衍的会被追、回避的会被切维度、说"不聊了"会收尾。对话结束后自动生成画像、追加时间线、提取行为模式。

技术上是完整的。但有个致命问题：**要让一个非程序员在终端里打字做自我访谈，基本等于拒绝所有人。**

这个版本的真正价值不在"能用"，而在**把追问逻辑从 Agent skill 里拆解成了可独立运行的模块**。状态转换规则、追问决策逻辑、题库数据结构——这些东西后来被 Web 版直接复用。

**学到的事：代码可以退后，但核心体验的模块化不能跳。把 Agent 的追问拆成独立的逻辑层——问答交互、画像展示、行动卡——每个模块独立验证，再组合。**

## V2：给它加一个行动指南引擎

V1 生成完画像就结束了。用户拿到一份「7 维度个人报告」——知道自己是什么模式，但不知道下一步干什么。

我加了一个行动指南引擎。不是 LLM 生成的——纯 Python 规则驱动，25KB 代码，零 token 成本。

你的 7 维度画像生成后，引擎把每个维度的模式特征匹配到四个体系：

- **易经** → 决策逻辑和能力图谱。10 卦模板，每卦对应一种处境——需卦帮你识别等待观望期，革卦对应变革转换期的能力不匹配。
- **王阳明心学** → 学习成长和防御机制。知行合一、事上练——不是懂了就完了，是做了才算。
- **道德经** → 价值观动机和防御机制。做减法、松绑——有时候你的问题不是做得不够，是想得太多。
- **儒家** → 人际交往和家庭身份。角色定位、关系导航。

每张行动卡只有四个字段：**处境诊断 → 哲学镜照 → 本周一事（30 分钟内可完成）→ 检验信号**。

不是建议，不是鸡汤。是一个具体的动作和一个验证标准。

为什么用规则引擎而不是 LLM？因为 LLM 在这个场景下的推理是"可以但不可控"的。同样的画像进去，两次可能给你不同的匹配结果。而**确定性**，在一个帮人做决策的工具里，比"看起来很聪明"重要得多。

**学到的事：不是所有地方都该用 AI。有些地方，规则比智能更可靠。**

## 最后：让那些不会用 Agent 的人也能用上

三版打磨下来，最深的体会是：**一个产品的核心体验可能藏在代码最深处，但能否触及用户取决于最浅处的入口。**

V0 的追问逻辑是最核心的东西。但如果入口是命令行、是 API key、是 pip install——这个核心体验永远传不到真正需要它的人手里。

所以有了 Web 版。浏览器打开就能用。交互方式从 Agent 对话改成了表单——这是妥协，但不是退步。63 道题本身的深度已经够了，追问可以等 V3 再加回来。

三种答题类型让输入摩擦降到最低：能点的点，能拉的拉，需要想的才好好想。画像和行动指南两步分开——先知道你是谁，再知道怎么做。每步你都可以停下来。
