# 同样的63题，我重做了一遍——从一个命令行脚本到一个能卖的产品

两个月前，我在Hermes里跑了一个自我访谈的skill。63道题，7个维度，用对话的方式帮你拆解自己。

当时觉得挺酷的。一个AI能追问你、能记住你说过的话、能生成画像。我把整个过程写成了一篇文章，叫"我用AI做了一次深度自我访谈"。

然后我开始想：这个东西能不能变成一个产品？

---

## 第一版：命令行里的Agent

最早的版本是个CLI工具。叫deeptalk。

你要用它，得先装Python，pip install，配DeepSeek API key，然后在终端里敲`deeptalk`。界面长这样：

```
> deeptalk
🪞 DeepTalk · 第一次对话

你最近脑子里在想什么？
>
```

技术上是完整的——Agent Loop状态机、三层记忆系统、63题题库、四家哲学合成引擎。WARM→OPEN→ASK→LISTEN→DECIDE→PROBE/SWITCH/CLOSE→REFLECT。九个状态，自动追问，自动切换维度，自动生成画像。

**但有个问题：没人能用。**

不是功能不够，是门槛太高。让一个非程序员装Python、配API key、在终端里打字——这基本等于拒绝所有普通用户。

---

## 第二版：Web App，但交互方式全换了

CLI是对话式的——AI问你一句，你答一句，AI判断要不要追问、要不要换话题。这是Agent。

Web App做不到这个。浏览器没法维持一个Agent Loop（至少我现在的架构不行）。所以我做了个妥协：

**把对话改成了表单。**

你看到的是一个网页，上面有63道题，一道一道往下填。进度自动保存，随时暂停。没有追问——你自己想多深就写多深。

这个妥协让我心里不太舒服。我觉得追问是自我访谈最核心的东西——AI在你敷衍的时候说"能再具体一点吗"，那才是深度。

但上线后我发现：用户不需要追问。至少第一次访谈不需要。63道题本身已经够多了，每道题你都要认真想——再加追问，人会跑。

---

## 四个具体的优化

### 1. 三种答题类型，降低输入摩擦

原来全是文本框——63道题每一道都要打字。后来我看了数据，发现有些题用户根本不想写——比如"你做决定前通常依赖什么？"这是个选择题。

于是改成三种模式：

- **free（自由输入）**：故事型、反思型问题，比如"你最艰难的一个决定是什么"
- **choice（点击选择）**：事实型问题，比如"你更信任数据分析还是直觉"，点一下就行
- **scale（滑块打分）**：程度型问题，比如"你对目前工作的满意度"，1到5拉一下

占比：63%自由输入、32%点击选择、5%滑块打分。用户打开后几乎不用犹豫——能点的点，能拉拉的，需要想的好好想。

### 2. 答题后不蹦结果，而是"你继续，等一下一起看"

原来的设计是63题做完立刻出画像。用户的反馈是"刚答完脑子还乱的，先别给我看这么多东西"。

改成了：答完题 → 先看到进度页 → 点"生成画像" → LLM跑 → 看画像 → 点"生成行动指南" → 四体系引擎匹配 → 看卡片。

两步分开，每一步你都可以停下来。不是一次性灌给你——是让你自己决定什么时候往下走。

### 3. 行动指南：不是给你标签，是给你"这周做一件什么事"

画像告诉你是谁。行动指南告诉你怎么做。

我用了四个体系——易经、王阳明心学、道德经、儒家——每个对应不同维度。纯规则引擎匹配，零LLM成本。

比如你的决策逻辑维度的矛盾点被易经匹配到"需卦"（等待观望期），行动卡会告诉你：这周做一件你一直想但没动手的事，30分钟内完成。检验信号：做完了是不是觉得"也就这样"。

不是心理建议，不是心灵鸡汤，是**可执行的一个动作 + 一个检验标准**。

¥9.9解锁完整手册。为什么收费？因为每次生成画像和行动指南都要调大模型——DeepSeek虽然便宜但不是免费的。收的钱基本够覆盖API成本。
