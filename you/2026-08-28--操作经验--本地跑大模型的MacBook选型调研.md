# 本地跑大模型的 MacBook 选型调研

2026-08-28 用 Hermes 做了一次「跑某个模型需要什么 Mac」的完整调研，方法可复用。

## 做了什么

调研了两个模型在 MacBook Pro 上本地运行的成本：

1. **Qwen3.8-Flash-Next**（125B-A6B MoE，见 [[raw/2026-08-28--公众号--Qwen3.8-Flash-Next发布]]）
   - BF16 全量 360 GB → 必须量化。MLX 4-bit ≈ 112 GB
   - 结论：需 128GB 统一内存 → 只有 16 寸 M5 Max 顶配，官翻约 ¥5.4 万起
2. **Qwen3.6-35B-A3B**（35B-A3B MoE）
   - MLX 4-bit 官方版仅 24.7 GB，GGUF Q4_K_XL ≈ 22.4 GB
   - 结论：24GB 内存的 M5 Pro 就能跑（官翻 14 寸 M5 Pro ¥16,999），预算内最优 ¥1.7-2 万

## 提炼出可复用的调研方法（五步）

1. **看激活参数定带宽需求**：MoE 模型每 token 激活参数量决定解码速度，总参数量决定内存需求。A3B 级别（3B 激活）消费级 Mac 就能跑流畅。
2. **实测量化体积，不靠估算**：直接拉 HuggingFace/ModelScope 仓库的文件清单加总（`/api/models/<repo>?blobs=true` 或 ModelScope repo/files API），比「参数量×0.5字节」靠谱，N-gram Embedding 这类附加模块经常被估算漏掉。
3. **Mac 优先找 MLX 版**：mlx-community 官方库没有的，搜第三方 MLX 量化（Vontra 等）或 GGUF（llama.cpp 也能跑 Mac）。
4. **内存门槛 = 量化体积 + 5-10GB 余量**：长上下文要另算 KV cache，GDN/线性注意力架构的 KV cache 远小于全注意力。
5. **价格查两个官方源**：Apple 官网商店页（嵌 JSON 里有各档 seoPrice）+ Apple 官方翻新店（listing 标题不含内存数，要点进商品页核对）。

## 一个洞察

「能不能跑」的判断顺序：先看**内存**（硬门槛）→ 再看**带宽**（速度体验）→ 最后看芯片代际（特性支持，如 MTP 投机解码）。公众号选题角度：「不是买起 M5 Max，是你的模型决定买什么 Mac」——按预算从低到高给三档配置方案，比堆参数实测更有传播力。
