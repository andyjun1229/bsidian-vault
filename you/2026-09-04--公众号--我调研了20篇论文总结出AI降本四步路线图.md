# 我调研了 20 篇论文，总结出 AI 降本的四步路线图

上周我干了一件费脑子的事：把 arXiv 上关于「Agent 怎么省钱」的论文翻了个遍，从斯坦福的 FrugalGPT 到最新的计划缓存，筛出 20 多篇有实测数据的。

为什么突然研究这个？因为我算了一笔账。

我的一人公司跑着几个 AI 产品，每月 API 账单稳定增长。有人说省 token 的办法是「少用点」「prompt 写短点」——这种话和「省钱就是少花钱」一样正确且无用。

读完这 20 多篇论文，我发现一个被忽略的事实：**Agent 最大的成本黑洞，不是模型不够聪明，而是它把 90% 的 token 花在了重复搬运历史记录上。**

## 一、先看清楚钱花在哪

Agent 的成本公式其实很简单：

**总成本 = 每轮调用的 token × 单价 × 轮数**

很多人盯着「单价」打转——换便宜模型、找免费额度。但论文们指向了另一个方向：**多轮 Agent 的输入 token 里，绝大部分是反复重发的历史对话和工具输出**。你第一轮问的问题，会在第二轮、第三轮、第十轮被原样再付一遍钱。

这意味着：在动模型之前，光是「少搬运」就有巨大空间。

## 二、四步路线图（按投入产出比排序）

### 第一步：三个零成本开关（当天见效，省 30-60%）

这是性价比最高的部分，不需要写一行代码。

**① 开前缀缓存。** OpenAI、Anthropic、DeepSeek 的 API 都支持把系统提示词、few-shot 示例放在最前面，命中缓存的部分按约一折计费。你什么都不用改，只要调整内容顺序——**输入费用立降 50-90%。**

**② 上语义缓存。** 相似的问题直接返回缓存过的答案。这不是纸上谈兵——AWS 和微软都已经在生产环境用这套东西。客服类、查询类 Agent 的命中率能到 30-70%。注意一点：相似度阈值要用自适应方案（VectorQ 论文的做法），固定阈值要么误命中要么浪费。

**③ 关掉不必要的深度思考。** 现在的模型大多支持思考档位调节。让 Agent 干简单步骤（格式转换、信息提取）时用低档，只有真正需要推理的步骤才开高档。

### 第二步：给输入瘦身（1-2 周，再省 20-40%）

**工具输出是最大黑洞。** Agent 抓一个网页、跑一条命令，返回的内容全量塞进对话历史，之后每一轮都带着它重新计费。解法是过一道「结构化摘要」再入历史——只留对后续决策有用的部分。

一篇 2026 年的论文给了实测数字：把对话历史蒸馏成结构化记忆，**token 减少 11 倍，检索质量不掉**。

另外一个反直觉的发现：自进化 Agent 的技能库会越来越臃肿——同一个要求在多个分支里反复出现。定期给技能库「去重压缩」，也是必要维护。

### 第三步：混合模型（2-4 周，再省 40-70%）

这是文献最厚的方向。核心思路一句话：**便宜模型先答，不确定再升级。**

开山之作是斯坦福的 FrugalGPT：便宜模型处理大部分请求，置信度不够的升级到贵模型，最高省 98% 还保住质量。之后所有「模型路由」研究都在这个框架里打转。

我最推荐的是一个免训练的简化版：让小模型对同一问题采样多次投票，答案一致就直接用，不一致才升级大模型。不需要任何训练，一个 if 语句就能落地。

进阶玩法是「错误成本矩阵」：给每个步骤标上出错的代价——格式化步骤用最便宜的模型，直接影响用户的步骤用最强的。**不同步骤的错误代价不同，模型档位就不该一刀切。**

### 第四步：把 Agent 本身变便宜（1-3 月）

最激进的路线：等你的 Agent 跑成熟了，把它的工作轨迹——包括什么时候调工具、什么时候写代码——蒸馏进一个小模型。注意是蒸馏「轨迹」不是蒸馏「答案」，这是 2025 年一篇论文的关键洞察：小模型要学会的是「什么时候查、什么时候算」的行为模式。

省下的不只是 token，是整个推理链条。

## 三、比省钱更重要的：质量护栏

读这些论文时我一直在警惕一件事：**所有降本手段都有静默劣化的风险。**

一篇叫 Agent Capsules 的论文给了我最大的警示：他们尝试把多个 Agent 合并成更少的调用次数来省钱，结果发现盲目合并会在没人注意的情况下悄悄劣化质量。他们的解法是「质量门控」——每次合并必须先证明质量不降。

这和我最近写 WikiSkill 论文解读时的发现完全同构：Google 的技能进化循环有四步，但真正防止系统退化的是人加的第五步——定期人工抽查。

所以我的路线图里有一条铁律：**每次降本改动，必须过质量门控；成本和任务成功率必须一起监控。**只看成本的优化，最终会优化出一套「便宜的垃圾」。

## 四、一个意外收获

调研到最后我发现，这些论文讲的套路，和两周前 Apple 那篇视觉论文是同一个哲学。

Apple 的 IVT 模型为了让视频推理变快，把「预测未来」这个昂贵的思考过程从推理阶段挪到了训练阶段——训练时学会预测，推理时直接回答，快了 5 倍。

你看，**「把昂贵的思考变成一次性的沉淀，而不是每次都重新想」**——缓存是这个思想的工程版，记忆蒸馏是它的数据版，模型蒸馏是它的能力版。

这跟王阳明说的「知是行之始，行是知之成」竟有几分暗合：真正的理解一旦内化，就不需要在每次行动时重新推演一遍。

**最好的降本，是让昂贵的思考只发生一次。**
