# 慢快双层架构——从机器人触觉到 FPGA 推理

2026-09-07 读了两篇 PAIR2026 报告论文，发现它们在解决同一个母题：**慢系统的规划能力 + 快系统的反馈闭环，怎么各司其职**。

## 论文一：RDP（Reactive Diffusion Policy）

`[[raw/papers/PAIR2026/谷国迎--Reactive-Diffusion-Policy.pdf]]` — 上交+清华，RSS 2025，机器人触觉模仿学习

核心主张：
- 视觉模仿学习（Diffusion Policy/ACT/π0）靠 action chunking 保时序一致性，但块内是开环的，触觉反馈来了无法响应
- 关键发现：简单把触觉塞进观测没用（DP 加触觉 ≈ 纯视觉），触觉必须进控制回路
- 灵感来自神经科学：人类接触任务 = 前馈预测动作（慢）+ 感觉反馈闭环微调（快）

架构拆解：
- 慢策略 = 潜空间扩散策略（1-2Hz，出动作块，保多模态建模）
- 快策略 = 非对称 Tokenizer（CNN 编码 + GRU 解码，触觉只进解码器，潜空间只留高层策略，<1ms 推理，24Hz 闭环修正）
- TactAR 遥操作：Quest3（$500）把触觉形变场实时渲染在 AR 里贴到机械臂末端，数据质量直接决定快策略能学到什么

工程要点：相对轨迹表示（不用逐帧 delta）、延迟匹配（丢弃预测块前几步）；消融显示两条"捷径"（缩小 chunk / temporal ensemble）都走不通。

## 论文二：FlightLLM

`[[raw/papers/PAIR2026/戴国浩--FlightLLM-FPGA大模型推理.pdf]]` — 清华+上交+无问芯穹，FPGA'24，FPGA 上跑 LLM 推理

核心主张：
- GPU 吃不到模型压缩的红利（只支持 2:4 稀疏；SIMD 位宽对齐让混合精度量化无法降访存），FPGA 可定制资源能吃到
- batch=1 时 LLM decode 是访存问题不是算力问题（GPU 带宽利用率仅 29-43%）
- FPGA 落地拦路虎是指令爆炸（LLaMA2-7B 全场景 1.67TB 指令）

三个解法：
1. 可配置稀疏 DSP 链：DSP 组级可重构，吃 N:M 稀疏红利，计算效率 +1.6×
2. Always-on-chip decode：decode 激活全程留片上，HBM 带宽利用率 35.6%→65.9%；HBM 放大块访问、DDR 放小块访问
3. 长度自适应编译：token 长度分桶复用指令，1.67TB→3.25GB（500×）

结果：比 V100S-opt 能效高 6.0×、成本效率 1.8×，定位是 batch=1 延迟敏感+能效敏感场景，不打大 batch（GPU 反超）。

## 我的关联观点

14 篇 PAIR2026 论文的完整解读见 `[[you/2026-09-07--AI技术--PAIR2026论文解读]]`，其中"跨论文观察"一节把这个母题扩展到七种形态（机器人控制/触觉感知/数值方法/物理学习/科学计算/世界模型/芯片架构）。

两篇领域隔很远（机器人触觉 vs 芯片架构），但架构同构：

| | 慢系统 | 快系统 |
|---|---|---|
| RDP | 潜空间扩散策略（1-2Hz 规划） | 非对称 tokenizer（24Hz 触觉闭环） |
| FlightLLM | prefill 阶段大矩阵乘 | decode 阶段片上闭环（常驻片上绕开访存） |
| 人类 | 前馈预测动作 | 感觉反馈微调 |

值得沉淀的原则：**复杂行为建模交给慢系统保表达力，实时反馈交给快系统保响应，中间用潜空间/片上缓存解耦**——这个模式在 Agent 领域同样成立（慢思考的 planner + 快反应的 reflex 层）。

另一个跨论文共识：**数据/输入质量决定快系统的上限**。RDP 里没触觉反馈采的数据训不出反应行为（掉分 30%）；FlightLLM 里压缩精度损失是系统要付的代价。上游输入不干净，下游快系统学不出可靠关联。
